# Bug Report: Daily publishing leaked rejected and incomplete products

**Date:** 2026-08-13
**Severity:** high
**Status:** fixed and verified

## Symptoms

- All 60 products marked `rejected` still had Chinese and English pages.
- 52 public cards lacked a Chinese explanation or inspiration.
- AICPB enrichment returned exactly 20 descriptions out of 49 on three consecutive days.
- The scheduled collection had started about 2 hours 20 minutes late on both observed runs.

## Expected Behavior

- Rejected and reader-incomplete products remain in `data/pool/` but never appear in public HTML or the sitemap.
- AICPB detail enrichment completes without starving the same trailing products every day.
- Daily collection avoids GitHub's known top-of-hour congestion, and the judgment layer can collect as a fallback before publishing.

## Reproduction

1. Count `status: rejected` files in `data/pool/`: 60.
2. Check the corresponding `site/p/<slug>.html` files: all 60 existed before the fix.
3. Inspect the last three AICPB raw batches: every day had 20 non-empty and 29 empty descriptions.
4. Replay the 49 detail URLs in order: requests initially returned 200, then the remaining requests returned a Nuxt 404 error page for the same known-valid URLs.
5. Inspect GitHub runs 31559830271 and 31663873093: they started at 03:21 and 03:25 UTC for a 01:00 UTC schedule.

## Root Cause Analysis

### Public page leakage

- **File:** `src/xocto/site.py`
- **Original location:** `build_context()` and `build()`
- **Introduced:** `2d8a23b` (2026-08-11)

`build_context()` treated every pool record as public data and never checked status or content completeness. In addition, `build()` only overwrote current pages; it never removed pages that were generated by an earlier build. Filtering context alone therefore would still have left rejected URLs online.

### AICPB enrichment starvation

- **File:** `src/xocto/sources/aicpb.py`
- **Original location:** `_enrich()`
- **Introduced:** `1ee235a` (2026-08-11)

The collector requested all product detail pages in a tight sequence. AICPB applies an IP request limit that surfaces as a generic Nuxt 404 rather than 429. `_enrich()` swallowed `HttpError`, retried the same fixed order every day, and permanently starved the trailing half of the list.

### Schedule reliability

- **File:** `.github/workflows/daily.yml`
- **Relevant change:** `0e9dba6` (2026-08-12)

The new schedule was placed exactly at minute 0. GitHub documents that scheduled workflow load is highest at the start of the hour and that runs can be delayed or dropped. The claimed 60-day disable risk does not apply: GitHub limits that rule to public repositories, while `laixi969-coder/xocto` is private.

## Fix

1. Publish only non-rejected products with both `summary_zh` and `inspiration`.
2. Remove stale generated product/report HTML after each successful render.
3. Add a design constraint that fails if rejected or incomplete product pages exist.
4. Split AICPB detail requests into batches of 15 separated by 61 seconds; expose the first failures and decode HTML entities.
5. Move GitHub collection to 06:17 Asia/Shanghai, pass the Product Hunt secret, run design checks, and retry a non-fast-forward push via rebase once.
6. Define a timezone-anchored Codex daily judgment/publish automation with collection fallback and full validation.
7. Add `.private/` as a git-ignored location for private notes.
