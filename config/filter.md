# 过滤规则

> **这是初稿，等蔡蔡给出手工分析样本后重写。**
> 这个文件决定了整个系统的信噪比 —— 它是"品味"，不是"逻辑"。
> Claude Code 在过滤阶段读这个文件，逐条判断，不写代码。

## 目标

每天进入的候选都先形成一条可追溯的发现记录，**不设首页条数上限**。只要是独立项目、
实质性的 AI 改造、已跑出规模的成型产品，或可验证的跨国供给缺口，就应进入当日机会流
并给出真需求判定。信噪比靠分层、标签和真需求判断建立，而不是靠编辑先行删掉未知领域；
说不清谁付钱的，仍必须写出它解决什么用户需求、什么痛点；只有连痛点都写不出才判「需求不成立」。不许写成「待验证」。
每天必须能从当日候选里交出一条方向判断。交「今天没有值得展开的」先查过滤是不是
把垂直切口、早期信号和成型产品误杀了——那是品味故障，不是市场空白。

主目标是找**能讲成一门生意的东西**：谁付钱、替代了哪一步旧工作、窗口在哪。
能抄的机制和投资观察是同一份判断的两面，不为了“看起来像好公司”挤掉更清楚的案例。
地产、营销、内容相关产品在质量相同时优先，但不能绕过第一档淘汰规则，
也不能因为赛道相关就降低证据门槛。
再一个只给开发者用的零件，除非它改了某层怎么收费，否则不要上首页。

## 先看来源：两类东西不能用同一把尺子

不同来源采回来的东西性质完全不同，**混在一起用同一套标准会两头都判错**：

| 来源 | 是什么阶段 | 怎么判 |
|------|-----------|--------|
| Product Hunt / Hacker News / GitHub / Hugging Face | 刚冒出来，几乎没有数据 | 走下面的三档规则，靠判断 |
| **AICPB** | 已经跑出规模，有真实访问量和环比 | **只看两件事，见下** |
| **官方博客 / 官方 Release** | 一手发布的行业变化，不一定是新产品 | 只作日报背景；不进入产品分析队列 |

**已跑出规模的产品单独处理，但仍是产品，不是市场背景。**
豆包、DeepSeek、Kimi 这种已成气候的东西，用"已饱和品类"那条会误杀；它们要进
「已验证生意」，做真需求判断：需求成不成立、窗口还在不在、该不该跟、从哪切。
「不要正面竞争」写在切入里，不是把它标成 `market_context` 藏起来的理由。

对已有公开规模的产品问三件事：

1. **真需求成立吗？** 买方是谁、旧行为刚不刚、交付能否确定。成立不等于该去做。
2. **环比异常吗？** 增速超过 +100% 的必须留下并说明原因（是真起量，还是上了什么榜、
   被哪个平台导流、还是数据口径变了）。
3. **窗口还在哪？** 排名平稳的头部也要判断：真需求成立但窗口已关，仍然是有效结论。

`market_context` 只留给**不是独立产品**的事：模型发布、价格战、监管、平台政策、
行业结构变化。一条公告不是新产品，只作日报背景。

**官方发布单独处理。** 它们可以解释能力、模型、平台或生态的变化，但一条公告不是新产品，
也不是“值得模仿”的充分证据。只写摘要直接支持的事实和明确可验证的影响；没有影响就不写。

## 第一档：不进入机会流（命中任意一条）

- **纯提示词套壳且没有可观察的新工作流、行业供给或采用信号**：只有在现有事实已足以确定其为重复界面时才排除；说不清它替代了哪一步旧工作时判需求不成立，仍进入机会流。
- **不是独立产品的行业变化**：模型发布、价格战、监管、平台政策标为 `market_context`，
  只进当日市场摘要，不做真需求判定书。
- **已是大众默认入口的独立产品不得标成市场背景**：通用聊天、搜索、模型入口只要是可核验产品，
  就进已验证生意并做真需求判断。切入必须写清窗口是否已关、不该从哪打、还可以从哪切；
  “别和它正面竞争”是判断，不是把它从机会流拿掉的理由。
- **API 中转 / 模型聚合商**：卖 token 差价的，不是应用。
- **纯目录站、榜单站、导航站**：本身不解决问题。（注意：AICPB 自己就是榜单站，
  但我们抓的是**它榜上的产品**，不是它本身 —— 别把这条规则套到 AICPB 来源上。）
- **没有独立项目或实质交付**：仅有无法识别的跳转页、无内容的页面或明显仿冒链接。
- **明显刷榜**：票数与实际内容量级严重不符，评论清一色同质化短句。

## 第二档：机会流优先级（用于排序，不是入选门槛）

- **替代了一个具体的旧工作流**：能说清"以前这件事是谁、用什么、花多久做的"。这是最强信号 —— 有旧行为就有真需求。
- **垂直行业而非"所有人"**：面向律所、货代、牙科诊所、独立站卖家这种具体人群，而不是"面向所有创作者"。垂直意味着他们真的和用户聊过。
- **AI + 非技术行业的早期变化**：优先找保险、建筑、地产、物流、制造、医疗、法律、财税、教育、零售、农业、能源、公共服务等领域里，某个旧流程第一次被拆开重做的产品；不是为了凑赛道，而是要能指明原来谁在手工做哪一步。
- **定价页写得明确且不便宜**：敢标 $99/月以上并说清按什么计价的，说明验证过付费意愿。免费或 $9/月的通用工具通常还没找到价值。
- **卖结果不卖工具**：按产出收费（每份报告、每个案子、每条视频）而不是按席位/月费，说明它敢对结果负责。
- **有非 AI 的壁垒**：独家数据、线下履约、行业牌照、已有客户关系。这类产品即使模型能力被抹平也还在。
- **增长曲线异常**：短时间内流量/星数陡增且不是靠一次曝光。
- **做这件事的人对得上**：能查到创始人自己就是这个问题的受害者，或者他的经历
  和这个问题严丝合缝。采集层已经记下了 builder，这条比产品本身更能说明问题。

## 第三档：存疑但保留（进入机会流，必须给出真需求判定）

- 中国团队做的出海产品 —— 蔡蔡关注，即使品类普通也留一条记录。
- 看不懂在做什么但数据很好的 —— 这类往往是认知盲区，值得留个名字观察一周。
- 旧业务/旧产品的 AI 改造——只有当它重划工作流、产出、收费方式、服务边界或交付链路时才保留；
  单纯新增问答、摘要或生成按钮不构成机会。
- 仅在一个国家或语言市场出现的产品——保留并检索另一市场是否已有本地供给；证据不足时标为“跨国机会待核验”。

## 判断顺序

1. 先识别是否为独立项目、实质 AI 改造、开源项目或市场结构变化；第一档才排除。
2. 其余项目均写入发现事件，二、三档决定展示排序和 `/req` 结论，不决定是否在当天消失。
3. `queued` 表示已具备进一步研究价值；`watching` 表示信息不足或需求仍待核验。两者都可公开。
4. 同日项目按首次发现时间倒序展示；不可用“每天前 N 条”替代完整机会流。

## 已采用的编辑口径

- [x] 以**能抄的**（可迁移机制）为主，能投的作为辅助判断。
- [x] 地产/营销/内容相关应用在同等质量时加权，但不降低淘汰门槛。
- [x] 每日完整展示首次发现的有效机会；不以固定条数截断。

## 本期市场摘要的发布门槛

市场背景摘要必须写明：谁在何时发生了什么具体变化，以及该事实对 AI 应用的成本、采用、交付或竞争意味着什么。
影响必须有材料支持，推断必须标为推断；禁止从一次发布推断整个行业已经转向。
只说发布财报却没有业务数据、分析师评级或股价标题、泛泛讨论 AI 趋势、只有公司名而无新增事实的，一律 rejected。
“非独立产品”“内容未提供具体细节”“公开材料不足”等分流理由和兜底文案不能当摘要；不得为凑条数保留。

正文独立讲清事实与意义，底部展示可追溯的新闻出处或数据来源；来源链接用于核验，不以链接代替摘要。
