# REQ 公开证据模式

这份规则将 REQ 真需求闸门用于 xOcto 的自动化公开证据判断。它不是对创始人的
对话式盲测：系统不能假装采访过用户，也不能要求读者代替系统去访谈。

## 运行原则

- 先走价值，价值闸门没有证据时，后面的共识、模式、求真不得判为成立。
- 结论必须站在买方一侧：谁付钱、不用会失去什么、交付能否确定发生。
- 价值对应功能、情绪或资产价值；三者都找不到买方价值，标注玛蒂尔德风险。
- 共识要指出卡在感知、想象、场景或利益哪一环；公开关注或收藏数不是持续采用。
- 模式必须说明钱可能来自 to C、to B、to G 或 to VC 的哪一方。只有融资叙事、没有用户付费路径时，标注每日优鲜风险。
- 求真检查产品是否贴近该工作的第一性目标、承诺能否确定性交付，以及安全与人工边界。
- 把昂贵技术或很多功能拼在一起、却没有强场景或买方价值时，标注貂丁风险。

## 输出约束

- 四道闸门仍按 value、consensus、model、truth 排列；每条都给结论、证据边界和理由。
- “待验证”只表示证据不足，不表示项目不好，也不等于让读者去做访谈。
- `next_validation` 必须是 xOcto 下一轮可自动收集的**一条公开证据**：例如官方定价页、客户案例、部署文档、公开使用数据、仓库 issue / discussion、可复现实测、独立评价或监管材料。
- 不得输出“访谈用户”“找一位用户”“确认用户愿不愿意”等要求读者执行的句子。
- 价值闸门没有过时，后面三关应说明“未进入：价值证据不足”，而不是假装已经完成判断。
