## 一句话定位

把本机 Claude Code 和 Codex 的会话日志变成可检索、可分析的知识库：
token 花在哪、上下文窗口用得多满、agent 摸了哪些文件和工具、
完整对话能全文搜索，还能从历史命令里蒸馏出可复用的工作流脚本。
运行时零外网请求，会话记录不出本机。

## 做这个东西的人

Dosu（dosu.dev）公司维护，自称"面向 agent 的知识基础设施"。仓库 `dosu-ai/decant`，
Apache-2.0，Bun + TypeScript 实现，近期主要提交者是 Taylor Dolezal（GitHub `teedole`）。
pool 里记录的 builder 是 `devstein`，可能是仓库创建者，无法核实其与 Dosu 的关系。

_判断：Dosu 自己做 agent 基础设施、天天跑 agent，dogfood 自己的日志——Decant 既是给社区的工具，
也是它主产品的引流入口。这类"公司核心业务 + 免费开源周边"的组合，维护动力比纯个人项目稳。_

## 它到底能做哪几件事

- **统一归档** → 把 Claude Code（`~/.claude/projects`）和 Codex（`~/.codex`）的日志归一进一个 SQLite 库
- **全文搜索** → 跨消息、工具调用、完整对话搜索
- **多维分析** → token、估算成本、上下文、活动、工具、MCP、文件使用分析
- **可视化浏览** → 会话、项目、文件、摄取诊断都能看；CLI 和本地 Web UI（127.0.0.1:3000）同一套数据
- **导出** → Markdown / JSON / 报告 / trajectory
- **蒸馏（distill）** → 从命令历史里提取确定性脚本、回放、agent 指令（AGENTS.md 片段），输出时自动打码密钥——这是它区别于纯记账工具的独有功能
- **本地 API** → OpenAPI 3.1 契约，agent 可以自己查自己的历史

**它明确不做**：不做云端、不做网络调用、不采集遥测；真实会话里可能有源码、prompt、凭据，
所以官方明确要求 issue 和测试一律用合成数据。

## 它在替代什么旧行为

以前想复盘"这个 agent 会话到底干了什么、花了多少钱"，只能去翻
`~/.claude/projects` 底下散落的 JSONL 原始日志，或者信厂商用量页的总数。
会话之间的关联、工具调用模式、"这周 agent 都在重读哪些文件"——这些问题
靠肉眼翻日志回答不了。

Decant 替代的是三件事：**翻原始日志**（→ 一个 SQLite 库 + 全文搜索）、
**算不清成本归属**（→ token/成本/上下文按维度拆开）、以及最特别的——
**把 agent 干过的活变成可复用资产**（distill 把一次成功的操作流固化成脚本/技能），
这已经不是记账，是把历史变资本。

## 商业模式

Decant 本身免费开源（Apache-2.0）。Dosu 的营收在它的主产品（agent 知识基础设施服务）上，
Decant 博客结尾的落点是"用它看清 agent 缺什么知识，再用 Dosu 补齐"。

_判断：这是标准的"工具引流"结构——分析工具免费开放换安装量和口碑，
真正的钱在"帮 agent 更快更便宜"的托管服务上。对 Decant 单品的商业判断没有意义，
对 Dosu 的漏斗判断才有意义。_

## 判断

**与 CodeBurn 撞同一个需求，恰恰说明这个品类成立了。**

两者一周内先后冒出来：CodeBurn 是个人开源（40 工具成本仪表盘 + 预算守卫），
Decant 是公司开源（Claude Code/Codex 会话库 + 检索 + 蒸馏）。
同一点痛同时被独立方选中，是"AI 成本失控是普遍问题"的最强证据。

**Decant 最值得注意的功能是 distill。** 记账工具只能告诉你"钱花哪了"，
distill 把成功的操作历史直接变成脚本、技能和 AGENTS.md 片段——
这就从"看账本"跨到了"把过去的活变成未来的杠杆"。这是它和 CodeBurn 的分水岭，
也是"知识基础设施"这个定位的真正落点。

**两个局限**：一是只覆盖 Claude Code 和 Codex 两个工具，覆盖面远窄于 CodeBurn；
二是它本质是 Dosu 的引流件，功能演进会服从 Dosu 主产品战略，而不是 Decant 独立产品的需求。

## 下一步看什么

① 三个月内 star 数能否破千、HN 热度能否兑现成持续采用——目前公开热度很低（10 分/0 评）
② distill 是否有用户公开报告"蒸馏出的脚本真的在复用"——它是唯一区别于记账的功能
③ 是否扩大覆盖工具（目前只有 Claude Code + Codex）——覆盖面是这类工具的生死线

## 可借鉴的做法

**产品逻辑**："分析你的历史"类工具里，最高级的一档不只是告诉你花了什么，
而是把历史**蒸馏成未来可直接调用的资产**（脚本、技能、指令）。
从"可见性"到"复用性"的这一步，值得任何做 agent 工作流工具的人抄。

**话术**："Turns the logs your agents write into real numbers."——把"让日志变成数字"写成一句
主张，本地优先和隐私就自然包含在里面了。

**分发**：免费开源 + 本地 API（OpenAPI 契约），让"agent 自己查自己的历史"成为可能——
把工具本身也做成 agent 可调用的节点，是开源工具参与 agent 生态的正确姿势。

## 结论

**有待观察。** 公司背景比个人项目稳，distill 功能独一份，但公开热度低、
工具覆盖窄、功能演进受 Dosu 主产品牵制。品类判断（成本失控是普遍痛点）
已经由它与 CodeBurn 的同日出现证明了，对单品再等等看。
