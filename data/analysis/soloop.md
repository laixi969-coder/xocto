## 一句话定位

给单人创业者的"审批优先"Agent 操作系统：一个 AI CEO 定计划、
AI CTO 写代码、AI CMO 找用户，但每一步要动手之前都先问你一声。

## 做这个东西的人

PH 页面由 Zac Zuo 发起，创始人 Wenhao Yu 在 launch 评论区自述——
此前在大厂做产品，团队能解决难题，但大量时间耗在等决策上：
会议、季度评审、汇报、交接。AI 编码工具让他一个人能出第一版，
但"选受众、找用户、读反馈、决定下一步"这些事没人替他做，于是做了 Soloop。
团队规模、公司实体：未披露。

_判断：创始人的痛点叙事非常具体——不是"缺工具"，而是"一个人要同时扮演
CEO/CTO/CMO 三个角色，且三个都做不深"。这是 solo founder 的真实处境，
也是这个产品选择做"代理公司"而不是"单点助手"的原因。_

## 它到底能做哪几件事

- **AI CEO** → 给一句业务描述，生成带周里程碑的路线图；
  它的工作不是写代码写文案，而是把计划攥在手里，标出每周哪些决定需要你判断
- **AI CTO** → 评估和拆解构建任务：一个功能是一天的活、一周的活，
  还是一个月都填不满的坑——给非技术创始人一个校准工时估算的参考系
- **AI CMO** → 负责分发：launch 计划、渠道选择、触达文案，
  默认设计成低成本或零成本渠道，贴合 solo founder 没营销预算的现实
- **审批优先的运营循环** → 把创始人输入的东西变成"一个下一步动作 + 理由"，
  等批准才执行；发布、研究、花钱、部署、改代码，全部等创始人点头
- **工作区记忆** → 回复、用户、代码改动、失败尝试都留在工作区，
  影响下一次推荐
- **每日审批循环** → 每天汇总 AI 团队做了什么 + 少数需要你拍板的决定

**当前分工**：Plan / Research / Social / Coding 四类代理，社媒执行目前以 Twitter/X 为主。

## 它在替代什么旧行为

以前单人创业者跑公司是"一个人打全场"：一小时做计划、一小时写代码、
一小时做冷启动触达，循环往复——三个角色都做，三个都做得浅；
更糟的是"什么都自己来"意味着带宽锁死，做产品的没时间找用户，
找用户的没时间读反馈。

而通用 agent 框架（CrewAI、AutoGen 等）的问题是反向的：它们能并行跑很多 agent，
但把"协调"这个任务丢回给创始人——你要在多个 chat 之间搬上下文、对齐计划。

Soloop 替代的是"一个人三班倒 + 自己当胶水"的工作方式：
把计划、执行、分发编排成一个围绕单一公司目标运转的团队，
创始人的角色从"什么都做"变成"批准所有事"。

## 四维评估

| 维度 | 结论 |
|------|------|
| 创始人-产品匹配度 | 创始人就是目标用户（大厂出来、一个人做产品），痛点叙事具体可信 |
| 产品洞察力 | "审批优先"把"agent 全自动"和"人肉执行"之间那个被忽略的中间态做成了产品核心 |
| 技术实现质量 | 早期阶段，评论区有用户反馈"CEO/CMO/CTO 不先给全貌只给细碎动作"，体验还不成熟 |

## 判断

**"审批优先"这个词组本身说出了 2026 年 agent 产品最大的取舍。**

过去一年大多数 agent 工具押注"全自动"：设个目标走开，祈祷它别跑偏。
Soloop 押相反的注：创始人仍然要做需要品味、风险承受力和远见的决定，
产品把这些决定用每日审批循环接住。评论区那个"发明了一个叫 Teri 的假员工
还给她分配工单"的段子，正是审批缺失的代价——agent 会编造，
审批是最后的防线。

**可迁移的规律：agent 的信任机制 = 产出草稿，不产出行径。**
评论区里一位跑了 25 个 AI 营销 agent 的创始人总结了让多 agent 保持理智的两条铁律：
agent 只出草稿不出动作；缺信息时提问而不是编造。
Soloop 把这两条做进了产品机制，这比任何"安全"宣传都有说服力。

**真正的风险是审批疲劳。** 当批准变成反射动作，审批就失去了意义——
一天点五十次批准，留下的审计记录反而成了"有人审过"的假象。
Soloop 目前没有展示对抗这个问题的结构性设计（批量、风险分级、
只给 diff），评论区已经有人在问这个问题。这是它从"早期产品"
到"可信赖工具"之间必须跨过的一道坎。

**另一个观察点**：评论里最真诚的呼声是"把已有产品接进 CMO 流程"，
说明创始人找到的用户是"已经做出东西、缺分发"的人，而不是"想从零开公司"的人。
如果产品往这个方向收敛，定位会更锋利。

## 下一步看什么

① 定价是否公开、按什么计费——决定"审批优先"能不能变成可持续生意
② 是否推出对抗审批疲劳的结构化机制（批量批准、风险分级、只显示 diff）
③ 三个月后用户的真实留存：多少人真的每天在用它"跑公司"，还是试用后弃用

## 可借鉴的做法

**产品逻辑**：做多 agent 产品，把"人审批"做成机制而不是设置项——
每次执行前给一个"推荐的下一个动作 + 理由"，批准才动手。
这比"全自动 + 事后可干预"更能建立信任，也更符合高风险的落地场景。

**话术**："宁可慢一点，也要让人保持控制权"——把取舍说出口
（approval-first 本身就是取舍宣言），比堆功能列表更能让人记住产品立场。

**定价结构**：未披露，暂无参考。

## 结论

**值得关注。** 审批优先是对"agent 失控焦虑"的正面对症，
PH 第 2 名的热度也说明它踩中了群体情绪。但产品还早：
定价没公开、体验粗糙（用户反馈先给细碎动作不先给全貌）、
审批疲劳的问题没有答案。它值得观察的方向是
"多 agent 协作的信任机制"这个 2026 年的核心命题。
