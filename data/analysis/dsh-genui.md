## 一句话定位

给 agent 的回复装上"脸"：模型在回答里直接写一段 JSON，浏览器把它渲染成卡片、图表、表单、测验这些能点的组件，点了还能把动作回传给模型继续改。文本还在，UI 已经活了。

## 做这个东西的人

omdsh-dev 组织维护，作者 taekchef（GitHub 同名），与 dsh-better-sidebar 同属一个组织。仓库 2026-08-13 建，MIT，TypeScript，0.8.0 开源首发，70 个提交，一周内从 0.2 走到 0.8，更新密度极高。

_判断：同一个组织连做侧边栏和 GenUI 两个插件，方向是"把 DSH 的交互层做厚"。这个组织押的是 UI 层而不是模型层——在"一切皆插件"的生态里，这个位置选得很准。_

## 它到底能做哪几件事

- **回复即 UI** → 模型用 `dsh-ui` fence 写 JSON 描述，组件随回复流式渲染，不用等整条消息
- **35 种组件** → 卡片、表格、图表、表单、标签页、折叠面板、文件树、时间线、diff、mermaid、3D 场景
- **交互闭环** → 按钮/开关/输入带 action 回传模型，模型改完 UI 再更新；同名动作 300ms 防抖
- **本地优先** → 判分、校验、展开折叠在浏览器就地完成，不占模型往返；测验答案本地判，零 token
- **安全白名单** → 组件白名单制渲染，模型注入不了 HTML/脚本；函数表达式经独立解析器解析，绝不用 eval
- **状态持久化** → 按"会话 + 内容指纹"保存，刷新恢复，LRU 200 块上限
- **双通道渲染** → 新版 dsh 走官方 fence-registry 流式管线；旧版/原版 dsh 走 DOM 通道自行挂载，0.7.2 起也支持流式
- **零侵入** → 没装插件的环境里 fence 只是代码块，不报错、不污染会话

**它明确不做**：不做跨会话状态持久化、不做 MCP 适配器、不做独立画廊页、不做 i18n（roadmap 里每条都给了理由）。边界划得很克制——它只解决"回答里长 UI"，不解决"UI 离开对话活"。

## 它在替代什么旧行为

以前想让 agent 输出可视化结果，是"文本 + 人肉搬运"：模型给你一张 ASCII 表或 markdown，你想要图表就得复制数据去 Excel、图表站，或者让 agent 写个脚本再跑。一次"看到结果"要 3-5 分钟，来回两三轮。Claude Artifacts 和 ChatGPT Canvas 把"可交互的预览"带进主流，但它们是"另开一个画布"，且生成的内容大多是静态的。

genui 替代的是这条搬运链，且往前走了一步：UI 直接在回复流里渲染，而且组件是"能点"的——点按钮回传模型，模型改 UI。它不是 Artifacts 的 DSH 移植版，它把"生成即交互"从"渲染静态结果"升级成"渲染可编程界面"。

## 判断

**这是六个插件里唯一一个押注"未来交互范式"的，但也是证据最少的。**

它的赌注很具体：agent 的输出会从"文本 + 代码块"演进到"结构化 UI"，而模型生成 UI 的安全姿势是白名单组件 + 本地优先 + action 回传。这套设计逻辑是对的——让模型自由输出 HTML 是事故，白名单是唯一现实路径；让判分这类状态在本地完成、不烧 token，是在给"AI 产品毛利"做贡献。

**可迁移的规律：模型生成的任何内容，都要先定义白名单，再谈自由度。** 以及，交互组件里凡是"状态判断"都本地做、只有"需要新信息"才回传模型——这是把生成式 UI 的边际成本压到接近零的通用手法。

**但它现在只是个 54 星的插件**。没有用户案例、没有企业验证，而且 Claude/OpenAI 已经在做同类能力（Artifacts、Canvas），DSH 官方理论上也能顺手内置。它作为"范式验证"有价值，作为"产品"还没站起来。

## 下一步看什么

① 三个月后 star 是否过千——看它是否被 DSH 官方插件推荐位带起来
② 官方 dsh 是否内置类似 fence 渲染——内置即判它死刑，同时也证明它协议的判断是对的
③ 有没有真实用户分享"agent 生成 UI 干活"的案例——这是范式成立的唯一硬证据

## 可借鉴的做法

**产品逻辑**：任何面向生成式 AI 的产品，如果要让模型输出结构化界面，照抄这套安全设计：组件白名单制渲染 + 独立解析器（不用 eval）+ 本地优先状态 + action 回传模型。这套组合同时解决安全（模型注不进脚本）、成本（状态判断不烧 token）、体验（组件能点）三个问题。

**话术**：无。README 是工程文档体。

**定价结构**：无。未披露。

## 结论

**有待观察。** 范式最性感、证据最少的那个。如果"agent 生成可交互 UI"真的是下一轮交互范式，它的协议设计值得直接抄；但作为产品，它还没拿到市场任何投票。记下它的机制，别记它的 star。
