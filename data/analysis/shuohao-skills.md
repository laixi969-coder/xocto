# shuohao-skills

## 一句话定位

把一本小说拆成能直接开拍的短剧素材包：角色设定、形象提示词、音色、分集大纲。

## 做这个东西的人

GitHub 账号 `eternityspring`，中文开发者，自称"烁皓"。
README 开头第一件事不是介绍产品，是**留微信号拉付费群**——说明他很清楚自己在卖什么。

_判断：这不是一个"顺手开源"的技术项目，是一个有明确变现意图的内容产品。_

## 它在替代什么旧行为

短剧改编的前期工作。以前这一段是：编剧读完小说 → 手写人物小传 → 美术出设定图 →
导演排分集大纲 → 制片列资产清单。一个团队三到五人，一部剧的前期做一到两周。

它把这一段压缩成"丢一本小说进去"。**旧行为极其明确，这是最强的真需求信号。**

## 商业模式

**开源引流 + 付费社群。** 代码 MIT 式免费放出，变现在微信群（"AI 短剧交流群（付费）"）。

这条路径在中国独立开发者里是标准打法，但值得注意它的取舍：
- 好处：零获客成本，GitHub star 直接转化为群成员，且群是高频触点
- 代价：收入上限被群规模锁死，做不大；且极度依赖个人 IP

_判断：定价逻辑站得住，但天花板低。这是"一个人的生意"，不是公司。_

## 硬数字

- GitHub 655 star
- 两个 skill：novel-characters、novel-outline
- 大纲 skill 内置 **13 道质量门全部脚本检查**
- 付费群规模：未披露

## 四维评估

| 维度 | 结论 |
|------|------|
| 创始人-产品匹配度 | 高。他自己在做 AI 短剧，产品是自用工具的外溢 |
| 产品洞察力 | 高。切的不是"生成视频"而是"开拍前的素材准备"——这一段最耗人力、最没人做 |
| 技术实现质量 | 中上。13 道质量门是脚本检查不是模型判断，工程上更可靠 |
| 市场时机 | 正好。AI 短剧在中国正热，但工具全在"生成画面"这一端拥挤 |

## 判断

这个项目最值钱的地方不是代码，是**它选的位置**。

所有人都在卷"AI 生成视频画面"，它绕到上游做"开拍前的素材准备"——把小说变成角色设定集、
把角色的外观声音气质变成可复用资产、把改编逻辑变成分集梗概和爽点表。这一段在传统流程里
最耗人、最依赖经验，也最没人愿意做成产品，因为它不性感、演示效果差。

**可迁移的规律：当一个赛道所有人都在抢最显眼的那一环时，价值往往沉在它上游那个又脏又累的环节。**
生成画面是红海，但"喂给生成器什么"是空的。

代价也很清楚：它把自己绑死在了个人 IP 上。README 第一屏就是微信二维码，
意味着这个产品的增长上限等于这个人的社群运营能力，而不是产品本身。
一旦他停更，655 个 star 一夜变成死代码。

它和"影策"（见下）其实是同一个判断的两种下注：一个赌工作流的**上游**（素材准备），
一个赌工作流的**容器**（画布集成）。谁对，取决于短剧生产的瓶颈到底在哪一段。

## 下一步看什么

1. **付费群规模能否突破几百人** —— 突破了说明社群变现路径成立，突破不了就是个爱好
2. **skill 数量是否继续增加** —— 停在两个说明他自己也没跑通全流程
3. **有没有人拿它真的产出了上线的短剧** —— 这是唯一能证伪"素材包能直接开拍"的证据

## 对你的可迁移点

**产品逻辑（高度相关）**：这正是 songo 缺的上游环节。你的工作流是"从灵感到成片"，
而它把"从小说到可开拍素材"这一段做成了标准件。**它的 13 道质量门尤其值得看**——
把创作质量变成脚本能检查的硬约束，这个思路可以直接搬到 songo 的每个环节上。

**话术**：README 的开场"丢一本小说进去，出这个"+ 一张成品截图，比任何功能列表都有力。
你做产品介绍时可以直接用这个结构：一句输入，一张输出，中间不解释。

**定价结构**：开源引流 + 付费社群这条路，对你不适用（你的客户是企业不是开发者），
但"免费给工具、收费卖认知"这个骨架可以换个壳——比如免费给营销团队工具，
收费做方法论陪跑。

## 结论

**强烈推荐。** 不是因为它做得多好，而是因为它选的位置和你的业务重叠度极高，
且它已经验证了"上游素材准备"这个切入点有人要。
