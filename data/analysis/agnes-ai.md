## 一句话定位

一个把「AI 干活」和「团队协作」放进同一张工作台的智能体工作空间：
文档、幻灯片、资料、任务和共享记忆都在一起，AI 不再是旁边的一个按钮，
而是跟着项目走、记得项目上下文、能和人并行推进的那一方。

## 做这个东西的人

新加坡 Sapiens AI 团队，创始人 Bruce Yang，团队约 150 人。
自研 7B 参数的推理模型 Agnes-R1 与 CodeAgents 多智能体推理框架，
官网自称「From a Global Top 10 AI Lab」。

_判断：这是典型的新兴市场打法——不在欧美市场正面碰 Notion 和 OpenAI，
先做东南亚、拉美这类模型和协作工具都还没被充分占领的市场。
官网把自家模型放在 Artificial Analysis 榜单上和 Kimi、GLM、DeepSeek 并排，
说明它在意的对手不是协作软件，而是模型厂商。_

## 它到底能做哪几件事

- **团队协作工作台** → 多人实时协同编辑文档和幻灯片，变更实时同步，
  支持批注评论、任务指派、跨设备异步协作
- **共享记忆（Shared Memory）** → 跨文档、对话和项目保留历史偏好与任务状态，
  新成员进入项目时能直接接手上下文
- **AI 生成与调度** → 自然语言调用 AI 生成内容、写报告、做 PPT、
  生图、生视频、生成可视化网页
- **免费全模态 API** → 2026 年 6 月 1 日起无限期免费开放文本、图像、视频 API，
  OpenAI 兼容协议（`https://apihub.agnes-ai.com/v1`），
  支持 Cursor、Claude Code 等 Agent 工具直接接入
- **模型矩阵** → Agnes 2.5 Pro Alpha（文本）、Agnes-Image-2.0（图像）、
  Agnes-Video-V2.0（视频），均主打与头部模型打平、价格更低

**它明确不做**：不做企业级 SSO/合规交付（conversiongems 评测指出
企业深度集成仍是短板），主打轻量团队和个人开发者。

## 它在替代什么旧行为

以前一个团队要「AI 帮我做 PPT + 全组一起改」，得同时开三样东西：
聊天工具里问 AI 要内容，把内容贴进 Google Docs 或飞书，
再在任务软件里记分工和进度。AI 回答的上下文、谁改了什么、
为什么这么改，全都散在各处，换个成员就丢一半。

Google Workspace 和飞书解决了「多人实时改同一个文件」，
但没解决「为什么这么改」。Agnes 押的是把 AI 的上下文也变成团队资产：
AI 记得这个项目的背景、决策过程和引用资料，成员不需要重述一遍。

## 商业模式

**Freemium + 免费 API 导流。**
- 免费档：每月 50 次请求（conversiongems 数据，2026-06）
- Plus：$19.90/月，每月 100 次
- Pro：$99.90/月
- 全模态 API 免费开放，作为获客入口

_判断：免费 API 是获客工具不是慈善。现在所有 Agent 工具
（Cursor、Claude Code、各类 WorkBuddy 生态插件）都要接模型，
把 API 价格打到零能最快塞进别人的工作流，等开发者用顺手了再谈收费。
这套「先用模型卡位、再收协作订阅」的组合，印度和东南亚的一批新模型厂商都在用。_

## 硬数字

- 流量榜：月访问 208 万，环比 +570.29%（2026-08），登全球增速榜
- 移动端上线两个月，注册用户破 300 万，日活超 20 万（团队自述，2026-06）
- conversiongems 评测引用「6M+ 用户、接近 $20M ARR、完成 A 轮融资」——二手来源，未获官方证实
- Agnes-2.5 Pro Alpha 在 Terminal-Bench v2.1 得分 67%，同榜 Kimi K3 为 85%、GLM-5.2 为 78%、DeepSeek V4 Pro 为 65%（Artificial Analysis 引用）
- 融资规模、团队融资来源：未披露官方口径

## 四维评估

| 维度 | 结论 |
|------|------|
| 创始人-产品匹配度 | 创始人从协作场景切入，团队有自研模型，是少见的「协作 + 模型」双线组合 |
| 产品洞察力 | 「共享 AI 上下文」是对协同工具只共享文件、不共享语境的正面回应，方向成立 |
| 技术实现质量 | 自研 7B 模型 + 多智能体框架，配合全模态模型矩阵，工程投入不小；但评测机构指出输出质量不稳、需频繁核验 |
| 市场时机 | 东南亚和拉美 AI 协作市场刚起量，切入时点早，但也意味着付费意愿待验证 |

## 判断

**mom +570% 需要打折看，但方向是真的。**

这个环比涨幅大概率是三件事叠加：6 月免费 API 活动带来的开发者流量、
移动端上线两个月的自然爬坡、以及 流量榜 上榜单带来的统计口径变化
（榜单产品本身会吸引更多访问被计入）。它的基数也低——上个月约 31 万访问，
2.08M 的绝对值在一众大厂产品里仍然很小。看这个产品不看单月流量，
看两件事：免费 API 有没有把开发者真正留下来，以及 $20M ARR 的说法有没有被证实。

**它真正的创新点是「共享上下文」这一层。** 文档协作工具解决文件同步，
它想解决语境同步——AI 记得项目为什么这么做。这个需求在远程团队里真实存在，
但能不能从「demo 很惊艳」走到「团队真的把知识库建在它上面」，
取决于 Shared Memory 的准确性。记忆系统一旦记错，比没有记忆更糟。

**它还不值得信任的地方**：商业化数字全来自二手评测和团队自述，
融资、ARR、用户数三个口径都对不上官方来源；产品成立时间短，
conversiongems 也承认「young company with limited documented support track record」。

## 下一步看什么

① 下月环比能否延续——mom +570% 是真实起量还是单次活动冲高，8 月是第一个验证窗口
② $20M ARR 与 A 轮融资是否有官方确认——没有就一律按未证实处理
③ 东南亚 / 拉美有没有企业级客户公开付费使用，而不是只有免费 API 开发者

## 可借鉴的做法

**产品逻辑**：如果你的产品既有 AI 能力又要多人协作，值得抄它的分法——
把「文件」和「语境」分开交付。文件层用成熟的协同编辑，
语境层用 AI 自动沉淀背景、决策和引用来源，让后加入的成员不用从头问起。
这是飞书 / Google Workspace 没覆盖的空位。

**定价结构**：API 免费 + 订阅收费的组合可以迁移——
用零价模型卡位开发者工作流，再把变现放在高频协作场景的订阅上，
比一开始就按 token 计费更容易起量。

**话术**：无。官网是典型的产品页文案，没有值得偷的句式。

## 结论

**值得关注，但尚需证据。** 产品方向（共享 AI 上下文）有真实差异化，
免费 API 策略也聪明，但商业化数字未经证实，mom +570% 更像营销峰值而非稳态。
记下来，下月用上面三条回头验证。
