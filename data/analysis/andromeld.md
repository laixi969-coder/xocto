## 一句话定位

给"安卓手机 + Mac"这对组合补上苹果那种接力（Continuity）体验：
安卓应用以独立窗口镜像到 Mac、支持随航式的应用接力、Finder 里直接翻
手机存储、通知和剪贴板双向同步——所有数据直连传输，不经过云服务器。

## 做这个东西的人

Ruoxin He，独立开发者。公开履历是 IceBox（Google Play 5M+ 下载）和
FilterBox 的作者。这次他做的是把安卓生态接到 Mac 上。

_判断：做过 5M 下载量应用的人再来做工具，说明作者有把"补缝"产品做到
规模的实绩，不是新手试水。IceBox 做的正是"安卓机顶盒/电视棒上想要更多
控制权"这类补缝需求，和 AndroMeld"安卓和 Mac 之间缺一条桥"是同一类
判断——巨头生态的排他性留下的缝，值得反复去补。_

## 它到底能做哪几件事

- **逐应用镜像** → 不像 scrcpy 那样整屏镜像在一个固定窗口里，而是多个安卓应用同时各开一个可缩放的原生感 Mac 窗口
- **应用接力（Handoff）** → 手机上开着的应用，可以直接在 Mac 上继续
- **输入与控制** → Mac 键盘打字、触控板手势操作；Spotlight 里直接启动安卓应用，应用出现在 Dock，还能把快捷方式放桌面
- **Finder 集成** → 在 Finder 里浏览安卓存储，支持拖放和 Quick Look；文件可直接拖进当前安卓应用
- **通知与剪贴板** → 双向同步，两套系统之间的边界基本抹平
- **连接方式** → USB 和 Wi-Fi 都支持，自动重连；APK 预览和安装
- **MCP 服务器** → 给 Claude Code、Codex 这类工具提供了 MCP server，等于让 agent 也能操作手机
- **免费 Web App** → 浏览器里同时控制最多 4 个安卓应用

**它明确不做的**：不把屏幕/音频流、剪贴板内容、文件经过云服务器中继，
无账号体系——所有数据在设备之间直连传输。

## 它在替代什么旧行为

"安卓手机和 Mac 之间传东西"以前是一连串将就：

一是**scrcpy**——开发者向的方案：命令行 + adb，整屏镜像在一个固定窗口，
一次只能看一个应用，没有 Finder 集成，普通人根本不会装。

二是**AirDroid 这类云中继**——要账号、数据经过服务器，传输敏感文件
心里发怵，且体验是"网页式"的，不是本地的。

三是**"发文件给自己"**——AirDrop 用不了（苹果生态排他），于是邮件发自己、
微信文件传输助手、云盘转存，拷贝粘贴两边倒腾。通知、剪贴板更是
干脆没有跨设备方案。

AndroMeld 替代的是这堆将就：把 scrcpy 的功能做成普通人能用的图形界面，
把云中继换成直连，把"发文件给自己"换成 Finder 直接拖。它补的是苹果
用自己的封闭生态制造的那条缝——这条缝苹果永远不会自己补。

## 商业模式

Mac App Store 发布，官网口径是"每个功能都能免费试用"，另有完全免费的
Web App。完整定价（是否订阅/买断、价格多少）**未披露**。

_判断：独立开发者 + 买断制（大概率）是这类工具的标准路径——没有云成本、
没有账号体系，边际成本接近零，定价空间反而更灵活。但也要看到天花板：
安卓 16+ 的机型要求 + Mac 用户里同时用安卓的人，市场盘子不大，
它和 IceBox 一样，是"小而稳"的补缝生意。_

## 判断

**这是"补缝"产品里做得最完整的样本。** 补缝的秘诀不是做功能，
是把大厂生态里已经存在的体验（Continuity）翻译到没有的地方——
AndroMeld 的每个功能点（逐应用镜像、接力、Finder、剪贴板）都能在
苹果 Continuity 里找到对应物，这比凭空发明功能靠谱得多。

**三个信号值得注意**：一是直连 + 无账号，把"不用云中继"当卖点，
这是隐私敏感用户的关键决策点；二是给 Claude Code/Codex 做了 MCP server，
让 agent 能操作手机——这个方向比镜像本身更前瞻；三是作者有 5M 下载的
先例，说明他知道怎么把这种工具推出去。

**但要冷静**：安卓 16+ 的要求意味着很多设备用不上；Mac + 安卓双持
的人群本身不大；苹果生态里类似的桥（如某些云剪贴板工具）也早有替代。
它的天花板是"小而稳"，不是爆发。

## 下一步看什么

① Mac App Store 的首月下载/评分——补缝工具的留存和口碑是硬指标
② 安卓 16+ 的硬性门槛会不会往下放（扩大可用设备基数）
③ MCP server 被 agent 工具链实际采用的证据——这是它比"镜像工具"多出来的那条未来曲线

## 可借鉴的做法

**产品逻辑**：想找市场缝隙，先去大厂生态里找"已经被教育好的体验"，
再把它翻译到另一个生态——用户不需要被教育，只需要被迁移。
补缝产品最好的起点是"对面已经有了"。

**话术**：官方一句话"Bring a Continuity-style experience to Android and Mac"，
用用户已知的产品（Continuity）命名未知的功能，零解释成本。值得抄。

**定价结构**：功能免费试用 + 免费 Web App + 数据直连无账号，先让人放心
再用体验谈付费；同时把"不经过云"做成明写的卖点。

## 结论

**值得关注。** 补缝方向对、体验完整、作者有 5M 下载的先例，且直连无账号
和 MCP server 两个点比同类走得远。但它注定是小盘子生意，验证它
该看首月下载和口碑，而不是增长曲线。它是"大厂排他性留下的缝"这个
判断的又一次验证。
