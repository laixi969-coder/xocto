## 一句话定位

把散落在每个 AI 工具里的模型、账号、技能和提示词收进一个本地桌面应用，
换工具不再从头开始——它是"AI 身份"的随身行李。

## 做这个东西的人

fy-agent 组织，核心提交者 `python-rust`。项目前身是 VibeKey——一个想把
AI 配置装进实体键盘的硬件想法，后来放弃硬件改做桌面软件，并脱胎于开源项目
CC Switch。Tauri（Rust 后端 + React 前端），覆盖 Windows / macOS / Linux。

_判断：从"实体键盘"到"跨平台桌面"，团队在早期就撞上了硬件分发的高墙，掉头很果断。
带着 CC Switch 的基因说明这是从既有用户里长出来的，不是从零造的需求。_

## 它到底能做哪几件事

- **管模型** → 统一管理供应商与模型选择，预设或自定义兼容接口，一键切换
- **管连接** → 集中管理 MCP 服务，同步到支持的 AI 工具
- **管技能与提示词** → Skills 和 Prompts 一处维护，不再每个工具里重复安装配置
- **管调度** → 本地代理转发请求、故障转移、模型可用性检查
- **管账本** → 汇总 token 用量与预估费用
- **管延续** → 从上次会话和工作区继续，配置备份与同步
- **支持的客户端**：Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、
  OpenCode、OpenClaw、Hermes

## 它在替代什么旧行为

以前换 AI 工具等于一切从头配置。模型供应商、API key、MCP 服务、技能、提示词……
每个工具各自存一份，散落各处，改起来要命，换工具后 AI 对你一无所知。
用户要么在多个工具里反复维护同一套配置，要么干脆只守着一个工具不换。

fyagent 用一份本地数据（SQLite，存于 `~/.fyagent`）把"我的 AI 配置"和
"某个具体工具"解耦——配置只写一次，再分发到各工具。导入配置时走 `fyagent://`
协议，先展示变更内容再决定是否写入。

## 商业模式

**源码可用（source-available），不是 OSI 定义的开源。** 自有组件和修改用
PolyForm Noncommercial License 1.0.0，非商业免费；商业使用需另行取得书面授权。
继承自 CC Switch 的部分保持 MIT。

_判断：典型的"个人工具走社区、企业功能走授权"双轨。现在只看到免费侧，
授权侧连价格页都没有，说明商业化还停在想法阶段。_

- 覆盖 Windows / macOS / Linux 的 x64 与 arm64

| 维度 | 结论 |
|------|------|

| 产品洞察力 | 抓准了"换工具从头再来"这个真实痛点，把配置层解耦是正解 |

## 判断

**它赌的是"AI 身份"会成为下一个要随身携带的东西。**
模型、技能、提示词、工作方式——这些在工具之间是通用的，绑定在任何一个客户端
上都是一种浪费。这个方向成立，且 CC Switch 的传承说明它已经有了一批存量用户。

**但"数字人格"是叙事，不是功能。** 现在交付的能力是配置管理：管模型、
管 MCP、管技能。这些都解决"配置分散"，没有解决"AI 了解我"。
"随身数字人格"的完整形态应该是行为记忆的迁移——换工具后 AI 仍然知道你
怎么工作、怎么思考。那是另一层难度，目前的账本、会话延续只是起步。

**73 个 open issue 是信号也是警报。** 对 204 star 的仓库，issue 密度偏高，
说明需求多、维护压力也大。如果 issue 以功能请求为主，是好事；如果以 bug 为主，
说明工程债在累积。

**授权模式是双刃剑。** PolyForm Noncommercial 能拦住商用竞争者，
但商业授权"另行洽谈"没有价格锚点，会吓退潜在付费者。这类工具的天花板
取决于它能不能成为 agent 工作流的"默认配置层"，而默认配置层通常是
免费且开放的。

## 下一步看什么

① 73 个 open issue 里功能请求与 bug 的比例——需求密度决定这是工具还是项目
② 商业授权页何时出现、怎么定价——只有免费侧说明还没人付钱
③ 三个月后客户端覆盖列表有没有新增——跟不上新 agent 工具就退回 CC Switch 的角色

## 可借鉴的做法

**产品逻辑**：多客户端并存是真实状态，把"用户配置"从"工具绑定"里解耦出来，
是任何多端产品的通用架构。给用户"先预览 diff 再写入"的导入体验，
比直接覆盖安全得多，也是建立信任的细节。

**话术**：无。README 是工程文档，没有可偷的句式。

**定价结构**：PolyForm Noncommercial + 商业书面授权的两段式，社区版免费、
商业版谈出来的结构适合工具类产品先圈用户再变现。但注意它连价格页都还没有，
这套结构目前只解决了"怎么合法用"，没解决"怎么收钱"。

## 结论

**值得关注。** 痛点真实、工程不糙，但它更像是 CC Switch 的延续而不是新物种，
"数字人格"的叙事和交付的能力之间有落差。记下来，盯客户端覆盖和商业授权两条线。
