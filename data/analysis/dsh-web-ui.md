## 一句话定位

DSH Web UI 的插件 + 皮肤集合商店——任务看板、Git 图谱、右侧面板、SSH、远程手机 UI、鲸鱼宠物、实时 token 统计，外加 8 套皮肤，一条命令装齐，还有一个可"先试穿再应用"的皮肤中心。

## 做这个东西的人

个人开发者 zhu1090093659（GitHub 同名），仓库 2026-08-12 建（官方发布前一天），237 提交，插件发布在 `@linxin666` npm scope。皮肤展示站 gallery.dsh-market.com。开源协议有疑点：README 声明 BSD-3-Clause，但 GitHub API 的 license 字段为 null（未检测到标准 LICENSE 文件）——上游媒体也点名过它"无 license 文件，法律上不可用"。

_判断：这是生态里 star 最高的插件（1184），但也是最"个人运营"的一个——协议不确定、皮肤靠整活、npm scope 和 GitHub 用户名对不上。流量最大和合规最差同时出现在它身上，是六件套里最典型的"社区红利 vs 工程规范"分裂样本。_

## 它到底能做哪几件事

- **任务看板** → 五列状态（待规划/待办/进行中/已完成/已失败），cron 定时执行、智能体会话执行与复盘跳转
- **Git 图谱** → 分支泳道与提交历史可视化
- **右侧面板** → 文件树、多格式预览（markdown/HTML/PDF/Office 等）、SCM 变更面板（stage/unstage/discard）、拖拽文件进输入框——和 dsh-better-sidebar 正面重叠
- **SSH** → Web 终端、SFTP 传输、端口转发、集群执行
- **远程手机 UI** → 扫码配对、SSE 实时消息（隧道不支持时自动降级轮询）
- **鲸鱼宠物** → 随 agent 状态切换动画、可投喂、成长系统
- **实时 token 统计** → TPS、LLM 耗时、上下文占用、缓存命中率
- **8 套皮肤** → Windows XP（Luna）、Minecraft、QQ2008、同花顺、交易终端（接入行情源）、蓝色幻想、鲸吟、龙的传人——全部"先试穿再应用"

**它明确不做**：不做任何 agent 核心能力——只做 Web UI 的外围和外观。任务看板是它最有功能价值的部分（cron 调度是真需求），剩下大部分是整活和美化。

## 它在替代什么旧行为

DSH 官方 Web UI 发布时功能很薄（实测者说"缺少文件管理、预览等能力"）。用户要任务管理得去外部工具（Trello/Linear 这类板子）、看 git 历史要开终端敲 `git log --graph` 或装 GUI、看 token 花费要事后翻 API 后台。

dsh-web-ui 替代的是这套"一个 agent 产品配三四个外部工具"的碎片化。它把任务板、Git 图、token 统计、SSH、手机遥控全部塞进 Web UI，用一条命令装齐。它的杀手锏是聚合包 `dsh-web-ui-all`——用户不用决定装哪个，全装就完事。它替代的旧行为是"为 agent 工作流手动组装周边工具"。

## 判断

**它是六件套里生态占位最成功的，也是产品价值最不稳的。**

它的成功不是功能，是"位置"：官方发布时 Web UI 是空的，它用一个聚合包把所有周边需求一次装齐，成了事实上的"DSH Web UI 第一站"。任务板的 cron 调度、SSH 是真功能，其余（宠物、皮肤）是生态的"生活感"——但正是这些整活内容在社区传播上贡献最大。

**可迁移的规律：对平台型产品，社区的第一站往往不是功能最深的，而是"一次装齐 + 好玩"的。** 聚合包降低了决策成本（不用选装哪个），整活内容提供了传播燃料。如果你在做平台生态运营，"留一个官方不做的位置给社区的第一站"比官方自己做更有效。

**它和 dsh-better-sidebar 的重叠**：右侧面板（文件树、预览、SCM）和 better-sidebar 正面撞车。better-sidebar 更工程（懒加载、扩展接口、520 星），dsh-web-ui 更聚合（1184 星）。这个重叠说明 DSH 的"右侧栏"是当前生态最拥挤的赛道——也说明官方留的这个坑最有流量价值。

**它的最大风险是合规**：license 字段为 null 意味着企业用户不敢用，这对一个想要长期价值的插件是致命伤。皮肤类内容也会随官方 UI 迭代快速贬值。

## 下一步看什么

① 是否补上标准 LICENSE 文件——null license 是拦在企业用户门外的硬伤
② 聚合包安装数（npm 下载量）能否查到——star 好看不等于有人装
③ 任务板/SSH 这类功能型插件是否持续迭代——整活会过时，功能会留下

## 可借鉴的做法

**产品逻辑**：做生态型产品的"第一站"插件，抄两个机制：聚合包（一次装齐，替用户做决策）和"先试穿再应用"（皮肤/模板类功能必须可即时预览、可完全回滚——把选择成本降到最低）。

**话术**：可借鉴。皮肤命名用"Windows XP (Luna) / QQ2008 / 同花顺"这种"一个词唤起一个时代"的命名法——对中老年开发者是怀旧钩子，对年轻用户是猎奇钩子，两个群体都点得进去。

**定价结构**：无。未披露，且协议状态存疑——反面教材：开源项目不补 LICENSE，等于把企业用户的嘴堵上。

## 结论

**值得关注。** 生态占位最强、商业想象最小。它证明了"聚合包 + 整活内容"是冷启动生态第一站的有效配方，也演示了协议不明的插件走不远的反面。看它，学的是"位置"而不是"产品"。
