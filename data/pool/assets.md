比如“开冰箱”这件事，很简单对吧，但要教会一个两岁儿童，你会发现“开冰箱”没那么简单，因为冰箱门有吸力，你在开的时候，肌肉记忆很自然的帮你处理了“先用一个比较大的力拉开 - 打开的瞬间判断门开了 - 快速卸力并判断卸多少 - 稳定力量缓缓拉开”，这个流程涉及对力量的掌控、对物理反馈的判断、对开合大小的预期和执行等背后的细节。

所以非常能理解机器人跑步比赛为什么一个个地扑街和撞墙: D

回到 vibe coding 上来，对 AI 开发工作而言，这个现象尤其明显。例如让几个 agent 同时开工，可能会是这样：

| Agent | 当前任务        | 你需要恢复的上下文           |
| ----- | --------------- | ---------------------------- |
| A     | 修复 UI 组件    | 布局、状态、样式             |
| B     | 调研 Agent 框架 | 方案、指标、依据             |
| C     | 产品预发布      | 品牌定位、视觉语言、设计约束 |

Agent 可以同时执行，但你阅读、审查和决策时，仍然需要进入不同的任务语境，上下文管理不止对于模型很重要，对于大脑也很重要。

除了切换时的注意力损耗，切换之后还有一些隐性的消耗，你看似投入到另一个任务中了，但实际上大脑对于上一个任务的上下文清理并不彻底，还有一些注意力残留，这可能比单纯的任务切换成本更能解释我感受到的疲惫。

一个显著特征就是我会时不时地看一下刚才 session 的任务状态，不是切过去，是看看 tab 上的状态是“转圈”还是“绿点”，我会不经意地惦记其它任务，这种“吃着碗里的看着锅里的”状态也是很耗神的。

Sophie Leroy 在 2009 年提出并实验研究了 Attention Residue，核心发现是**当一个人从尚未完成的任务切换到新任务时，一部分注意力仍停留在旧任务上，从而降低新任务中的表现**。

09 年的研究肯定不是基于驾驭多个 agent 进行的，但道理相通，并且在 AI 时代这个现象反而被放大和普及了。

过去亲自开发一个功能，可能需要几个小时或几天，虽然任务难，但大部分时间都围绕同一个问题思考。现在只需要五分钟把任务交给 Agent，就可以开始另一个任务，但交出去的任务不等于在心理上结束的任务。

![](https://assets.arieszhou.com/Screenshot%202026-11-21%20at%2018-30-38.jpg)

任务在计算机中是异步执行的，在大脑中却不一定能完全异步卸载。这就形成了大量未关闭的认知任务，有任务意味着有消耗。AI 产生信息太快了，我们的理解、判断和验收能力有点跟不上，这对于认知来说属于多维度的持续压力，骆驼身上的稻草堆积的又快又多，自然很容易感到疲惫😫。

# 关于前额叶

回到文章标题，本来想用“疲惫的脑门子”，实属是才疏学浅、文笔拙劣，本着直抒胸臆的态度，我确实是感觉脑门紧所以并没有认为这个命名有什么问题，但 GPT 从神经科学和代谢的角度给我分析之后，表示其实是「前额叶」的代谢变化与疲劳表现，呈现在表面上就是头皮紧张，并建议我使用“疲惫的前额叶”作为标题，有专家建议并且这个建议更显的高大上，我自然是欣然采纳。

关于论证和分析的过程与依据，有太多专有名词很难理解，经过两轮明确要求用它浅显易懂、措辞明确的沟通方式进行友好交流后，我理解下来是这样的意思：前额叶皮层与工作记忆、目标维持、执行控制等功能密切相关，持续高认知控制需求的任务，可能伴随特定前额叶区域的代谢变化和疲劳表现。

任务切换成本、信息处理压力、持续认知控制、机制维护与恢复不足，共同导致脑力过劳，感到疲惫。

所以压力的来源不是单一某个维度的，比较有效的办法不是避免所有高强度负荷，而是提高负荷与恢复的匹配程度，并且在衡量匹配时，考虑到曾经没有注意到过的注意力消耗，留出余地，别总想着榨干自己。

与羽毛球同理，运动员能获得好的表现，靠的不是始终维持较低心率或避免剧烈波动，而是采取更经济的技战术、强度分配与即使恢复。

想要改善认知压力，需要区分：

- 有价值的高强度思考，与不必要的认知切换；
- 主动选择的专注，与被 Agent 通知牵引的被动响应；
- 真正的休息，与只是从一个任务切换到另一个任务；

以及参考番茄钟等注意力管理方法最初要解决的问题：**为持续注意力提供边界**。

我高高兴兴地冲进了 AI 布置的高并发陷阱，让我有能力同时开始更多工作，却也使我失去了这种边界。

接下来要做的事情就是：降低认知负荷，调整工作节奏，给自己恢复的时间。

# 最后

我，我今年读过的很多书、博客、newsletter，以及听过的播客，很多地方都产生过关于“AI 为什么没有让我更轻松”的困惑与探讨。或许问题并不是 AI 没有提高效率，而是效率提升之后，我们很快用更多任务填满了释放出来的空间。

我们害怕自己错过这阵风，我们焦虑自己没有大成果，我们变成了过去吐槽过的压榨打工人的资本家（屁股决定脑袋），但我们戏称自己在压榨 Agent，但只有在一次累的不行或一次生病之后，才会意识到我们在压榨自己。

过去，我们经常思考如何让机器执行得更快；现在，也许应该开始思考怎样让机器更少打扰和挤占我们。这不只是个人时间管理问题，AI 可以不知疲倦地执行任务，但人不行。

当机器的执行力不再是主要瓶颈，我们或许需要重新学习的，不是如何同时做更多事情和更快地做事情，而是如何保护和经济有效地分配自己有限的注意力。

别着急，慢慢来，Agent 的长程任务以小时记，但人的长程任务以月/年记，希望你能好好休息❤️。
