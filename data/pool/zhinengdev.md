# Zhinengdev

![截图](https://zhinengdev.oss-ap-northeast-1.aliyuncs.com/x-phone-vscode-demo.jpg)

最想离开工位的时候，往往是刚让 Claude Code 跑完一轮修改、正在等测试结果的时候。人可以先去沙发上躺一会儿，可要是测试挂了，只想追问一句「哪条断言没过」，难道还得起身回电脑前？

我给自己做的 VS Code 扩展 **Claude Code Config Helper（LLS CCAI）** 加了一个「远程办公」入口，就是为了这几句话。电脑留在书桌上，手机用浏览器打开同一个项目、同一段对话。从手机发出的下一条消息，会进入电脑上的 Claude Code 会话；等它回复，手机也能看到结果。这就是我说的**躺起编程**。

## 躺在沙发上，适合做什么？

我不想把桌面 IDE 缩成巴掌大。真要对照两个文件看几十行差异，我还是会回电脑前。手机最顺手的是**看结果、给方向，以及及时喊停**。拿测试失败举个例子，在同一个会话里可以这样接：

> **在电脑前：** 跑一下这个项目的测试，先不要改代码。  
> **到了沙发上：** 把第一条失败用例的预期值和实际值列给我。  
> **如果还没看清原因：** 先停在这里，我回电脑看差异，不用继续改。

中间不用把终端输出复制到另一个聊天窗口，也不用在手机上拖鼠标找那一行报错。关键不是让手机写得比键盘快，而是离开键盘以后，那一句有用的追问还能接得上。

## 为什么不用远程桌面，或者直接在手机上开个 AI 聊天？

这三种方式都能用，但解决的不是同一个问题。想点某个设置、看浏览器里一个按钮有没有错位，远程桌面更合适；想问一个和项目无关的语法问题，手机上新开一个聊天就够了。我想做的是第三件事：**接着电脑上刚才的工作说下一句话**。

比如测试输出了两条错误，我只想问「第二条和第一条是不是同一个原因？」。这句话在新聊天里几乎没意义：哪两条？哪个项目？刚才跑的是什么命令？但在刚跑完测试的那段会话里，「第二条」有指向，不用先把一屏日志从电脑搬到手机。对我来说，能省掉的是这一趟来回，不是那几个字的输入时间。

## 一个具体例子：月底到期的测试为什么红了？

下面拿「领取一个月体验」做个例子：假设你正在做这个功能，有个测试刚好卡在 1 月 31 日。

**离开书桌前，给它一个小任务。** 不要只发「帮我修一下」，而是告诉它：「只跑套餐到期日期相关的测试。告诉我第一条失败用例的输入、预期值和实际值，先不改文件。」这样等手机收到回复，你要做的是判断，不是从一大段输出里找重点。

**躺下后，先补规则，再决定改不改。** 假如失败用例的输入是 `2027-01-31`，现在就有一个值得人来决定的问题：「一个月」是固定加 30 天，还是加一个自然月？如果业务规则是后者，2 月没有 31 号，目标日期就应该是 `2027-02-28`。比起直接说「让测试通过」，这时更有用的一句是：「先告诉我实现和测试各自按哪种规则算，不要为了让它变绿就改预期值。」

**回到电脑，再看真正需要大屏的部分。** 比如把日期计算和对应的测试放在一起，看这次修改有没有顺手改掉其他套餐逻辑。手机上那几句话已经把问题缩小到一个边界条件，坐回去不用再从整套测试的第一行看起。

## 主会话和并行会话怎么选？

手机端会让你选主工作区或并行任务。我的建议很简单：**凡是带「刚才」「继续」「第二条」这种指代的追问，都回原会话发。** 如果测试是在主会话跑的，就别刚切到并行会话便问「为什么红了」——项目还是那个项目，对话历史却不是同一份。

并行会话更适合一个能独立说明白的问题。比如主会话在看月底的失败用例，可以让另一边只读检查：「项目里还有哪些地方把一个月写成了 30 天？列文件和位置，别修改。」两边可以分开思考，但仍然面对同一套文件；不要让它们同时改同一个日期函数。

## 三步试一下，不用装手机 App

**GitHub 源码仓库：** <https://github.com/liliangshan/claude-code-config-helper>

1. **先在电脑上跑通一次。** 在 [VS Code 扩展市场](https://marketplace.visualstudio.com/items?itemName=liliangshan.claude-code-config-helper)安装 **Claude Code Config Helper**，确认发布者是 `liliangshan`。打开侧栏的 **LLS CCAI**，按引导选择或下载 Claude CLI，配置自己的模型服务。先在电脑上发一句话，确认能收到回复。
2. **只绑定一个想试的项目。** 用 VS Code 打开项目文件夹，点聊天输入框下方的「远程办公」，登录工作区账号，绑定当前目录。第一次建议选个测试项目，方便看清手机发出的消息到底进了哪个会话。
3. **在手机浏览器里接着聊。** 登录同一个工作区账号，选中刚绑定的电脑、项目和主工作区。第一句可以只问「想理解这个项目，我应该先读哪个文件？先不要改代码。」把手机和电脑摆在一起看一遍，之后就知道离开工位时能做什么了。

第一次连接，如果手机没出现预期的回复，不必先重装扩展。我会按这个顺序看：

- **找不到项目：** 先看手机和扩展登录的是不是同一个工作区账号，再看绑定的是不是当前打开的文件夹。模型服务的 API Key 不是工作区账号，两者用途不同。
- **项目在，但显示离线：** 看电脑有没有合盖睡眠、VS Code 窗口有没有关掉。绑定只说明之前授权过这个目录，不代表电脑此刻还能接任务。
- **显示已连接，但对话看起来不对：** 对照电脑名、项目名和任务区域。尤其是同时开了主会话和并行会话时，先找刚才那条消息，不要急着把同一条修改指令再发一遍。

## 哪些事我会留到回电脑以后？

我会在手机上确认「下一步查哪里」，但不会因为看见一句「测试通过」就让它发布。测试通过能回答的是这组用例有没有报错，不能替我看出一处不该出现的文件改动。涉及批量改文件、数据库变更、提交或上线，我更愿意回到 VS Code，把差异和执行范围看完整再决定。手机上点停止，也别当作撤销键：已经写进文件的修改，回到电脑上仍然要检查。

还有一个前提：**电脑不能关机或睡眠，VS Code 和扩展也要保持运行、联网。** 手机是遥控器，不是另一台替你跑任务的电脑。模型请求还是发给你自己配置的服务商，工作区不提供模型额度。

第一次试，不妨先在手机上问一个只读问题，看着同一句话出现在电脑上，再等回复回到手机。你最想躺着完成的是哪一步：看测试结果、补一句要求，还是在它改错方向时及时点停止？
