# Community

昨天晚上用 AI 从 0 开始 2 小时就完成了一个插件的开发，用于表格转置的插件，希望对你们有用！

我不想重复写正文了，正文说明就偷懒从 blog 粘贴了过来，对这个工具有想法的可以直接评论区留言:

---

最近我第一次尝试开发了一款 Obsidian 插件， 项目叫 `OB Toolbox`，  
昨天晚上已经上架到官方的插件市场，获取方式:  
> 打开 obsidian → 设置 → 第三方插件 → 社区插件市场 → 搜索 `md toolbox` 后安装

对应的项目地址:  
[obsidian 插件页]( https://community.obsidian.md/plugins/ob-toolbox)  | [github 主页]( https://github.com/Knowckx/ob-toolbox)

目前的话只加入了一个功能：**转置 Markdown 表格**。


## 为什么要做这个插件

自从把 Obsidian 作为主力笔记工具之后，我越来越喜欢用 Markdown 管理自己的笔记。

除了同步有一点麻烦，Obsidian 综合来说应该是目前最好的笔记产品？ 反正我对比过很多了，全部各有各的问题。

但 Obsidian 对 Markdown 表格的支持，始终没有那么完善。平时查看和简单编辑没什么问题，一旦需要做稍微复杂一点的处理，就会发现缺少很多顺手的小工具。

我经常遇到的一个需求，就是**转置表格**。

例如，把下面这个三行表格：

| A | 1 |
| --- | --- |
| B | 2 |
| C | 3 |

转置成：

| A | B | C |
| --- | --- | --- |
| 1 | 2 | 3 |


这个功能源于我对编辑空间利用率的一点执着：

> 我总是希望尽可能减少内容占用的行数，更充分地利用横向编辑区域。

有没有人和我一样...哈哈

过去我的处理方式很直接：

复制表格 → 发给 AI → 要求 AI 转置 → 再复制回 Obsidian

当然能用，但一来一回还是有点麻烦。

正好我还有其他想加的小功能，这次干脆给自己写了一个插件。

## 使用方法
用户侧的使用方法很简单：

1. 把光标放到需要转置的 Markdown 表格中，任意一个单元格都可以。
2. 按下 `Ctrl + P` 呼出 Obsidian 命令面板。
3. 搜索并执行 `Transpose Markdown table`。
4. 插件会自动转置整张表格，并在原位置完成替换。


## AI 让第一次插件开发变得很顺利

这是我第一次开发 Obsidian 插件。

如果放在以前，我大概率要先去研究 Obsidian 的插件结构、编辑器 API 、命令注册方式，再花时间处理构建配置和各种细节。光是把这些基础知识摸清楚，可能就已经消耗掉了大部分兴趣。

但现在有了 AI ，整个过程顺利了很多。

我只需要把核心需求描述清楚， 这些输入和输出都很明确的逻辑，AI 基本上都能处理。

我真正需要做的，是告诉它我要什么、检查结果是不是符合预期，再把不合理的地方继续讲清楚。

**对于这种边界明确的小工具，AI 已经把开发门槛压得非常低了。**

## 又苦涩，又快乐

做完这个插件之后，我的感觉其实有点复杂。

一方面，我作为一个程序员，确实越来越强烈地感受到自己正在被 AI 淘汰。

过去需要程序员花时间学习、查文档、调试和积累经验才能完成的事情，现在只要把需求描述清楚，AI 就能完成其中的大部分工作。

这种变化不可能不让人苦涩。

但另一方面，我又觉得自己遇上了独立开发最好的时代。

以前想做一个工具，创意只是第一步。后面还有技术栈、开发成本、调试、发布和维护，一层一层的门槛很容易把一个小想法压死。

现在这些门槛正在快速降低。

只要你知道自己需要什么，能够把问题讲清楚，再愿意花时间验证结果，一个人**甚至是毫无开发经验的小白**就可以把过去停留在脑子里的想法真正做出来。

所以我的感受就是：**旧的程序员身份正在贬值，但创造东西的能力正在变得前所未有地便宜。**


## 后面准备继续往里面塞工具

`OB Toolbox` 目前只有 Markdown 表格转置这一个核心功能，但我不准备只做一个单功能插件。

后面我在使用 Obsidian 的过程中，如果再遇到类似的小问题，我会继续把对应的工具放进来。

计划中还会加两个功能:
- 类似 onenote 的简单公式计算功能
- 在外部复制网页/markdown 后 粘贴到 obsidian 中会多出很多空行的问题

我的目标不是做一个功能特别复杂的大插件，而是做一个自己真正会长期使用的小工具箱。  
哪里不顺手，就补哪里。

最后: 

对程序员来说，这可能是一个让人焦虑的时代。

对创造者来说，这可能又是最好的时代。
