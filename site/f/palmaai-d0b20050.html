替代什么旧工作

替代企业目前用零散 MCP 网关、手工配置的 API 密钥、分散在各助手中的权限设置以及事后人工翻日志的临时做法。

商业判断

它押注的不是某个 AI 助手，而是企业采用 MCP 后必然出现的“谁能用哪个工具、以什么参数、由谁批准”的治理缺口；成败取决于能否在客户自有基础设施中快速落地并被审计方接受。

01

产品做什么

官网把产品描述为“每个 Agent 与每个工具之间的一层策略层”：所有 MCP 服务器和 Skill 通过一个连接器下发，按 IdP 组分配，并跟随用户进入 Claude、ChatGPT、Copilot、Cursor 等不同客户端。能力范围包括参数级策略判断、高风险调用的人工审批与法定人数、PII 与密钥在传输中脱敏、可离线验证的防篡改审计并推送到 SIEM，以及带版本和扫描的 Skill 与 Pack。部署形态声称支持本地、VPC 乃至完全气隙环境，但平台地图页需要提交企业邮箱才能查看，具体功能边界尚无法从公开文本完整核实。

02

谁使用、谁付钱

使用者是已经让员工用多种 AI 助手调用内部系统（如 Salesforce、Slack、GitHub、Snowflake）的企业 IT、安全与合规团队；付费者通常是 IT 或安全预算的负责人。痛点是员工各自接入 MCP 工具导致权限失控、敏感数据外泄、高风险操作无人批准、事后无法向审计证明“谁让哪个 Agent 做了什么”，这类审查在每次新工具上线和季度审计时反复出现。

03

实际工作流

典型流程是：管理员在 Entra、Okta 或任意 OIDC 提供方中按组授权，用户打开任意受支持的助手即获得对应连接器；Agent 发起工具调用时，请求先经过身份与权限校验，再对实际参数（渠道、金额、字段）执行策略，命中高风险规则则暂停并通知指定审批人；通过后凭据从企业 vault 临时换取，PII 在到达工具前被脱敏，最终把调用归属、参数、结果、耗时与成本写入防篡改审计。Skill 则以不可变版本发布，扫描通过后才被提供给 Agent。

04

收费与单位经济

输入未披露定价页，因此无法确认是按席位、按调用量还是按部署实例收费，也不能写成免费或订阅。可推断（非已验证）其企业本地/VPC 部署形态更接近年度企业合同加实施服务，单位经济取决于单客户部署与运维成本能否被合同规模覆盖；气隙与自托管会抬高交付成本，需靠较大席位基数摊薄。

05

采用证据与缺口

可确认的采用信号有限：投资方 D11Z 与 Plug and Play 在官网被引述为既是投资方又是客户，属于公司披露的自我陈述，不构成独立审计的客户数或留存证据。官网展示的成功率、调用量、成本等数字是产品界面示意，不能当作真实运营指标。缺少公开客户案例、定价、文档与第三方评测，无法判断实际部署规模与续费情况。

06

竞争与壁垒

与直接使用通用模型或各家助手自带权限相比，Palma 的差异在于跨客户端的统一策略与可离线验证的审计，且建立在开放 MCP 标准与客户自有基础设施上，降低锁定顾虑。壁垒条件是：策略引擎对真实参数语义的判断足够准确、与 IdP 和 SIEM 的集成足够深、以及审计证据被外部审计方认可；若这些只是薄封装，通用网关或云厂商原生治理功能可以快速覆盖。

07

如何解读这轮融资

本轮为 pre-seed，金额与原币由确定性层给出，投资方名单不等于领投名单。该阶段说明公司已把“企业级 MCP 治理”讲成可演示的产品叙事并获得早期机构与战略投资方支持，但不证明需求验证、收入或留存。资金用途未披露；下一里程碑应是从演示走向可核查的生产部署、公开定价与至少一个可引用的客户案例。

08

可能失败在哪里

第一，若企业客户不愿把治理层部署在自有基础设施，或部署周期远超“数周”的宣称，销售周期与交付成本会吞噬早期资金。第二，若 MCP 生态或主要助手平台把权限、审批与审计内建为标准能力，Palma 的中间层价值被压缩。第三，策略误判导致合法调用被阻断或敏感调用被放行，会直接摧毁安全团队的信任。第四，审计证据若不被外部审计方接受，核心卖点失效。

09

可借鉴的做法

可借鉴之处是把治理做成“默认最优路径”而非附加审批：一次授权随身份组流动、跨客户端复用，并用可离线验证的审计把合规成本转化为销售理由。对创业者而言，选择一个标准正在形成、但平台方尚未内建治理的缝隙，并以客户自有基础设施部署来化解数据外流顾虑，是合理的切入方式。

10

下一步看什么

下一步应观察：是否公开定价与部署文档；是否出现可独立核验的客户案例与部署时长；D11Z、Plug and Play 之外的付费客户数量；以及主要 AI 助手平台是否推出原生 MCP 权限与审计功能，从而改变竞争格局。
