01

产品做什么

Humanos 围绕 AI 代理构建风险网络：通过 Agent SDK 持续采集运行时事件，为每个代理生成 0–100 的动态风险评分，并提供可验证的运行时证据与风险历史。产品分为免费的风险管理（Know、Prove、Control）和定制的 Risk Intelligence API，后者面向保险、银行、合规与审计方输出风险信号、承保与定价情报、审批与理赔情报。官网还列出 Guardrails、MCP 即将推出、TypeScript/Python/C# SDK 以及 humanos.verify() 执行前验证等能力。

02

谁使用、谁付钱

使用者包括部署 AI 代理的企业开发与风控团队，付费者可能是需要持续风险情报的保险公司、信贷机构、银行合规与审计部门。痛点在于代理行为实时变化，传统问卷和事后日志无法回答“它能做什么、有多大敞口、有何保障、是否需人工审批、风险是否在变、出事时发生了什么”。官网称其已服务 350+ 金融科技、医院与保险公司，但这是公司披露，未提供审计或独立验证。

03

实际工作流

客户在数分钟内安装 SDK 并获取 API key，代理运行时事件被持续摄取；Humanos 标准化并评分，生成可验证风险档案与执行收据。执行前可调用 humanos.verify() 校验身份、授权与限额，必要时请求人工审批或撤销凭证；事件通过 Webhook 驱动集成。风险档案可私有或公开分享，供银行、保险、审计方复用，实现“一次测量、持续验证、网络内复用”。

04

收费与单位经济

官网定价页显示风险管理层免费，包含 Agent SDK、持续风险评分、风险历史与运行时事件摄取；Controls API 与 Risk Intelligence API 为定制，需联系销售。未披露具体价格、计费单位或合同结构，因此单位经济无法从现有证据推断。可确认的是其采用免费获客、向金融与合规决策方销售定制风险情报的潜在分层模式。

05

采用证据与缺口

官网客户页列出 InsureNow、Agentics Credit、Numo、Lusíadas、DataWhisper 等生产案例，并称覆盖 350+ 金融科技、医院与保险公司；InsureNow 案例详述其将 Humanos 风险情报接入承保、监控、续保与理赔证据，风险档案每 24 小时刷新。这些均为公司披露，缺少独立客户数、留存、收入或续约数据。融资记录显示其完成种子轮，投资方包括 Anthemis、Critical Ventures、Start Ventures、Springbank，但投资方名单不等于领投名单。

06

竞争与壁垒

与通用大模型或单点日志工具相比，Humanos 的差异在于跨代理、跨平台的运行时证据标准化与可移植风险声誉，以及执行收据对“授权范围与触发事件”的证明能力。壁垒取决于网络效应：越多保险、信贷与平台方采信其风险信号，代理越有动力接入。但若通用模型厂商或云平台内置类似验证与评分，或金融方自建标准，其护城河可能被压缩。

07

如何解读这轮融资

种子轮说明资本认可其从代理身份与授权切入风险基础设施的方向，但资金用途未披露，无法判断是投入研发、合规认证还是市场拓展。下一里程碑应是可验证的付费风险情报合同、保险或信贷方的实际采用深度，以及风险评分与理赔结果的相关性证据。

08

可能失败在哪里

第一，若保险与信贷方不采信其风险评分，或要求自建模型，Humanos 可能沦为数据管道而非决策层。第二，代理风险评分若无法证明与真实损失或违约相关，其风险情报定价能力将受限。第三，免费层与定制层之间若缺乏清晰转化路径，收入可能长期依赖少数大客户。第四，合规与数据隐私要求（如 GDPR）可能限制跨客户风险信号复用。

09

可借鉴的做法

Humanos 的做法值得借鉴：不直接卖“AI 安全”，而是把运行时证据转化为金融方需要的可验证风险信号，并用免费 SDK 降低接入门槛、用网络效应提升复用价值。创业者应关注其如何把技术证据翻译成承保、信贷等具体决策语言。

10

下一步看什么

可验证的下一指标包括：Risk Intelligence API 的付费客户数与合同金额、保险或信贷方是否公开采用其评分定价、风险评分与理赔或违约结果的相关性数据，以及 MCP 与 C# SDK 等路线图功能的实际交付。
