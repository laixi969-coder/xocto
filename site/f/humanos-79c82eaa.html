Humanos

Humanos 是面向 AI 智能体的风险网络：通过 SDK 与 API 采集智能体身份、授权、控制措施和运行时证据，生成持续更新的 0–100 风险分，并把可验证的风险画像复用于信贷、保险、审计等场景。

替代什么旧工作

替代以问卷、静态合规审查和事后日志排查为主的 AI 风险流程，也替代各机构为每个客户单独搭建智能体授权与审计集成的做法。

商业判断

最关键的商业判断是：Humanos 卖的不是单点风控工具，而是把“智能体执行证据”做成可跨机构复用的风险基础设施；成败取决于能否让足够多的执行方与承保/放贷方同时接入同一网络。

01

产品做什么

官网披露的产品分为三层：Agent SDK 提供持续风险分、风险历史与运行时事件接入；Controls API 覆盖身份与权限、护栏、运行时执行、人工授权和交易限额；Risk Intelligence API 面向保险、银行、合规与审计方输出定制风险信号。公司还提到 humanos.verify() 在执行前验证、审批捕获、凭证撤销和 Webhook。产品范围横跨监测、控制与对外风险情报，但具体评分方法、模型细节和误报率未公开。

02

谁使用、谁付钱

使用者包括部署 AI 智能体的开发与风控团队，以及保险承保方、放贷方、支付与资金管理团队、医院合规方和审计方。付费者更可能是需要持续风险证据的金融机构与受监管企业，而非单纯写代码的开发者。痛点是智能体行为随时变化，传统一次性尽调无法回答“它能做什么、有什么护栏、风险是否在变、出事时发生了什么”。

03

实际工作流

典型流程是：客户在智能体运行环境中安装 SDK 或调用 API，接入运行时事件、钱包/支付交易证据、授权与权限信息；Humanos 标准化并打分，形成可私有或公开的已验证风险画像；执行前通过 verify 检查授权，必要时触发人工审批，高风险动作可被拦截或撤销；执行后生成签名执行回执。保险场景中，承保方拿到的是结构化风险信号而非原始客户数据，画像按日刷新，用于承保、监测、续保和理赔评估。

04

收费与单位经济

定价页显示 AI 风险管理为免费，包含 Agent SDK 的持续风险分、风险历史与运行时事件接入，以及 Controls API 的身份权限、护栏、运行时执行、人工授权和交易限额；Risk Intelligence API 为定制报价，需联系销售。因此已知收费点是面向保险、信贷、审计等机构的风险情报与定制集成，但具体价格、计费单位和合同结构未披露。单位经济无法从公开信息推断，若免费层带来大量低价值事件而机构侧销售周期长，毛利与获客成本需要验证。

05

采用证据与缺口

官网列出 InsureNow、Agentics Credit、Numo、Lusíadas、DataWhisper 五个客户故事，并称风险信号“翻译”到 350+ 金融科技、医院和保险公司，但这些均为公司披露，未见独立审计或留存数据。InsureNow 案例称其将 Humanos 信号接入自研承保框架，画像每 24 小时刷新，执行回执用于理赔评估；这属于合作与集成描述，不等于已产生保费或收入。公司还称获得 Mastercard For Fintechs 2026 竞赛，并处于 SOC 2 Type II 审计中、对齐 ISO 27001。缺少付费客户数、ARR、续约率、风险分预测有效性等证据。

06

竞争与壁垒

与通用大模型或日志平台相比，Humanos 的差异在于把身份、授权、控制措施和运行时执行回执绑定成可验证、可携带的风险画像，并试图让承保方和放贷方复用同一套证据。壁垒条件是网络效应：执行方越多，风险情报越有统计价值；机构越认可，执行方越有动力接入。但评分模型本身可被复制，真正的护城河取决于数据独占性、监管认可、与支付/身份标准的深度集成，以及能否证明风险分与实际损失相关。

07

如何解读这轮融资

本轮为 Seed 轮，披露金额为 320 万美元，按 2026-09-28 欧洲央行汇率折算约 281 万欧元；投资方包括 Anthemis、Critical Ventures、Start Ventures、Springbank，但名单不等于领投名单。该阶段说明公司已从产品概念走到可集成 SDK 与客户合作，资金支持其继续搭建风险网络；资金用途未披露，不能推断为销售扩张或模型研发。下一里程碑应是证明机构侧付费合同、风险分与承保/信贷决策的实际挂钩，以及跨客户网络复用。

08

可能失败在哪里

第一，风险分的预测有效性若无法用实际损失或违约数据验证，保险与信贷机构不会把它纳入核心决策，产品会退化为审计日志工具。第二，网络效应需要双边同时启动：执行方不愿为免费监测贡献数据，机构方又要求足够样本才付费，任何一边冷启动失败都会拖慢增长。第三，智能体行为与监管标准快速变化，若评分口径不被监管或承保方接受，定制项目会变成高成本服务。第四，客户案例目前多为集成描述，若无法转化为可披露的付费与续约数据，融资叙事与商业现实之间会持续存在缺口。

09

可借鉴的做法

对 AI 产品创业者而言，Humanos 的可借鉴点是把“执行前授权 + 执行后证据”做成标准化 SDK，让风险数据在客户与金融机构之间可携带，而不是只卖一个仪表盘。另一个做法是用免费风险管理层获取执行侧数据，再向承保、信贷等高价值决策方销售风险情报，但必须尽早验证风险分与真实损失的相关性。

10

下一步看什么

下一步应观察：是否披露付费机构数量与合同金额；风险分是否被承保方用于实际定价或额度调整；InsureNow 等案例是否从“集成中”变为“已上线并产生保单”；以及 SDK 接入的智能体数量、事件量和风险分与实际事故的校准结果。
