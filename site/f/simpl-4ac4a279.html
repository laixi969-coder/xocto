SimpL

SimpL 是面向 B2B 销售团队的 AI 销售操作系统，用公开数据、专有知识图谱与深度学习找出该联系谁、何时联系，并生成个性化 LinkedIn 消息与跟进，最终以“成功付费”的方式按实际举行的合格会议计费。

替代什么旧工作

替代传统 SDR 外包/线索代理机构、按席位收费的销售互动工具，以及销售代表手工做公司调研、写开场白和跟进邮件的重复劳动。

商业判断

最关键的一点是它把定价锚定在“已举行的合格会议”而非席位或订阅，这既降低了采购门槛，也把交付风险从客户转移到 SimpL 自身，能否盈利取决于会议转化率与单会议成本的控制。

01

产品做什么

根据官网，SimpL 把公司研究、相关信号识别、个性化消息撰写、跟进与对话管理整合在一个平台中，并宣称是“销售团队的 AI 操作系统”。其文档还提供 Agent API 与 MCP 接口，允许外部 AI 代理读取看板、筛选机会、生成与审批草稿，但实际发送由用户浏览器中的 Chrome 扩展在 LinkedIn 上执行。产品范围覆盖从目标设定到首触、跟进、回复的完整外联链路；官网未披露底层知识图谱的具体数据来源、覆盖行业与准确率指标。

02

谁使用、谁付钱

使用者是 B2B 销售团队及其销售代表，付费方通常是销售负责人或公司，痛点是找到“值得联系的公司与联系人”并写出不像群发的内容，这一工作每天发生且高度重复。官网称“被最好的团队使用，另有数十个销售团队”，但未给出客户名称、行业分布或团队规模，因此客户画像只能从产品设计推断，缺少可核验的采用证据。

03

实际工作流

流程分三步：先与客户共同确定目标、报价、合格标准与单价；随后平台依据目标与所售产品做公司研究、识别触达信号、生成基于具体上下文的 LinkedIn 首触与跟进草稿，销售团队审批后由 Chrome 扩展在 LinkedIn 发送并管理对话；最后当会议实际举行且符合事先约定的标准时计费。Agent API 文档显示草稿状态从待审批到发送完成有明确流转，并设有“就绪门禁”，未就绪时禁止批准发送。

04

收费与单位经济

官网定价页写明按“已举行的合格会议”收费，单价从 70 欧元起、可超过 150 欧元，按月结算，无席位费、预付金或启动费，未出席不计费，改期仅在真正举行后计费。这是公司披露的定价，不是审计结论；单位经济上，收入等于单价乘以有效会议数，成本主要来自研究、生成与外联执行，若会议转化率低或合格标准被放宽，毛利会被侵蚀，但具体成本结构未披露。

05

采用证据与缺口

可确认的采用证据有限：官网称有“最好的团队”和数十个销售团队使用，并展示了融资消息，但未提供客户名单、留存、会议量或收入数据。融资记录显示其完成 pre-seed 轮，投资方包括 Techshop Capital 与 Vento Ventures，这只能说明资金支持，不能当作需求验证或产品胜出的证据。

06

竞争与壁垒

与通用大模型相比，SimpL 的差异在于把知识图谱、信号识别、外联执行与按结果计费捆绑成闭环，并用 Agent API 让第三方代理接入其队列与审批流程；与旧流程相比，它把调研、写作、跟进合并到一个界面。壁垒成立的条件是：信号质量与个性化效果持续优于通用模型直接生成，且按会议计费的模式能维持正毛利；否则通用模型加简单脚本即可复制其表层功能。

07

如何解读这轮融资

本轮为 pre-seed，金额与投资方由确定性层给出，说明公司处于早期验证阶段，资金可能用于产品与市场起步，但资金用途未披露。下一里程碑应是证明按会议计费模式下的单位经济可行，例如可核验的合格会议量、客户续约与单会议成本，而非仅扩大团队。

08

可能失败在哪里

第一，按结果付费意味着 SimpL 承担外联失败的成本，若合格会议转化率低于预期或客户放宽合格标准，毛利可能为负。第二，依赖 LinkedIn 与 Chrome 扩展执行发送，平台规则变化、账号限制或扩展失效会直接中断交付。第三，个性化质量若被客户视为“仍是 AI 群发”，续约与口碑会受损；此外客户数据与合规责任划分在官网未充分披露。

09

可借鉴的做法

可借鉴的做法是把定价与客户真正在意的结果（举行的合格会议）绑定，并用明确的合格标准与就绪门禁控制交付质量；同时通过 Agent API 把产品嵌入客户已有的 AI 工作流，而不是要求客户更换工具。

10

下一步看什么

下一步应观察：官网是否公布可核验的客户案例与会议量、按会议计费模式下的客户续约率、单会议成本与毛利，以及 LinkedIn 平台政策变化对 Chrome 扩展发送路径的影响。
