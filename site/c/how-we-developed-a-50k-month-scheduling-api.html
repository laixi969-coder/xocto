Spurwing 排程 API

Spurwing 把排程能力做成 API 卖给开发者和 CTO，让他们不必从零自建多日历、时区、多人可用性同步，创始人自报月收入 5 万美元，项目已于 2024 年关停。

01

真需求判断

真需求判断

想要非必需

自建排程是真实且重复发生的工程成本，外包给 API 有明确省时逻辑；但它是可替换的基础设施件，客户随时能换供应商或自建，加上项目最终关停，说明留存和定价权都不牢。

如何赚钱

向软件公司和咨询公司按 API 使用收费，客户是开发团队而非终端排程用户；具体定价档位素材未给出。

它替代了什么旧行为

替代开发团队从零自建排程模块，以及拼装多个排程 API 的做法。

02

首批用户来源

素材未提及具体首批客户来源，只说发布时聚焦软件开发公司和咨询公司。

获客渠道 开发者定向客户反馈渠道客服支持

03

可借鉴的打法

  1. 01把内部基础设施拆成独立产品：Spurwing 原本是母公司 Healthie 的核心排程模块，验证可用后单独对外卖。
  2. 02明确不跟 Calendly 抢终端用户，只服务开发者，把定位写进对外话术。
  3. 03用免费开源组件市场（widgets、apps）做开发者侧的引流入口。
迁移到 AI 生意

对做 AI 生意的：把模型能力包成 API 卖给开发者的路子可迁移，但要吸取教训——纯基础设施件容易被替换，需在数据、工作流或垂直场景上加锁，否则留存撑不住。
