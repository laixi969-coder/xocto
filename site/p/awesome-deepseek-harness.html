值得借鉴的一点

围绕单一模型的生态聚合站，可借鉴其构建开发者工具链的模式。

它替人省掉了哪一步

以前要找 DSH 插件，只能自己逛 GitHub 的 dsh-plugin 主题，一个仓库一个仓库点开看 README——没有分类、没有维护、没有质量信号。它替代的是「自己翻主题标签」这件事：把发现流程从「逛仓库」压缩成「看目录 + 复制安装命令」。

可借鉴的做法

产品逻辑：任何新技术生态里，「官方不做的索引」都是低成本的占位打法——不需要技术发明，需要整理纪律 + 持续更新 + 双语可读。先占位置，生态成了就是入口，生态不成成本也不高。可以搬到任何你判断会热、但官方还没铺基础设施的方向。

一句话定位

DSH 生态的地图——把散落在 dsh-external/hub 目录和 GitHub dsh-plugin 主题下的插件、工具、基础设施，按功能领域整理成一份持续更新的目录，每个条目一行描述一个链接。

做这个东西的人

0xsline，个人维护者。122 次提交，最近一次 2026-08-14，仓库致谢 Linux Do 社区。中英双语 README，有贡献指南和 CATALOG.md 完整目录文件。

判断：目录型产品是「官方不做、社区抢做」的典型空位。DeepSeek 官方只给了 plugin 主题，没人帮生态建索引，0xsline 占了。这类位置有一个特点：谁先占，谁就是默认入口。

它在替代什么旧行为

以前要找 DSH 插件，只能自己逛 GitHub 的 dsh-plugin 主题，一个仓库一个仓库点开看 README——没有分类、没有维护、没有质量信号。它替代的是「自己翻主题标签」这件事：把发现流程从「逛仓库」压缩成「看目录 + 复制安装命令」。

它替代的旧行为本质上是搜索引擎式的发现，而在生态早期，策展式发现几乎必然胜出——因为条目太少，搜索全是噪音，策展有方向。

判断

它本质上是 DSH 生态的期权：买的是「DeepSeek 把 harness 生态做成」这个前提。 如果 DSH 成，它是第一个被找到的入口；如果 DSH 不成，它就是又一个 255 star 的死链接仓库。作为阅读材料，它是当下理解 DSH 生态最好的单点入口；作为产品，它没有独立于生态的生存能力。

对从业者的价值：它是一份可对照的「agent 插件还有什么可做」清单——对着它的 15 个分类看哪些还是空的，比对着需求文档想产品方向快得多。
