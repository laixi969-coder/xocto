一句话定位

DSH 官方没有终端界面的补位插件——把 Claude Code 那种全屏交互终端原样搬到 DeepSeek Harness 里，像素鲸鱼、状态行、Esc 回滚、上下文进度条，npm 一条命令装完。

做这个东西的人

作者 ccch1mneyyy（GitHub 同名），另有协作者 T-Auto、CikeSeven 等，甚至带 AI 辅助提交。仓库 2026-08-13 建（版本历史可追溯到 8/5 内测期），MIT（8/14 从其他协议改为 MIT），npm 包名 dsh-cc-tui，当前 0.4.0，117 提交。被 DeepSeek Harness 官方公众号收录为"内测用户精选插件"。

判断：这是六件套里唯一拿到官方公众号背书的。作者公开说是"补位之作"，摆明了吃官方没做 TUI 这个缺口；官方收录等于官方承认这个坑存在且暂时不填。

它到底能做哪几件事

  • 全屏终端交互 → Claude Code 式全屏界面：/ 命令菜单、工具调用卡片、markdown 表格/代码高亮、@ 文件引用、Shift+Enter 多行、全文搜索
  • 像素鲸鱼顶栏 → 40×25 手绘像素精灵，启动播放手绘动画（眨眼→喷水→摆尾），窄终端（<64 列）自动收起
  • 实时工作状态行 → 28 种动画指示器、上下文占用 ≥80% 亮黄 / ≥95% 亮红预警、回合结束统计
  • 双击 Esc 回滚 → 对话回滚到任意历史消息，走官方 fork 服务，消息可编辑重发
  • 上下文进度条 + TPS 仪表 → 五段着色进度条实时读数 + 流式 TPS gauge 和 sparkline，速度语义色（≥50 绿 / ≥20 黄 / <20 红）
  • 思考流式展开 → thinking 边生成边展开，回合结束自动折叠，Ctrl+O 展开全文
  • 四套 agent 预设 + 主题 → standard/code/minimal/cordis，light/dark/dark-ansi 三套色板 + JSON 自定义主题，/theme 热切换
  • i18n 中英双语 → /lang 热切换，OS locale 自动检测；支持官方 MCP 客户端

它明确不做：不改 DSH 核心，fork/resume/compact 全走官方服务，卸载即完全还原。对官方机制依赖极深——这是它的安全声明，也是它的天花板。

它在替代什么旧行为

DSH 官方发布时把 TUI 从仓库里移除了（提交记录明写 cleanup: remove TUI package and legacy dsh entrypoints，并把 Web UI 定为主上手路径）。于是用 DSH 只有一条路：开浏览器进 localhost:3080。对住在终端里的 CLI 极客，这是降级体验——他们用 Claude Code、Codex 都是全屏终端：状态行、命令菜单、上下文占用、速度表一目了然。

dsh-TUI 替代的就是"用 DSH 必须开浏览器"这个行为。它把 Claude Code 的终端体验整体移植过来，让"习惯终端的人"不用改变习惯就能用 DSH。它替代的不是某个旧工具，而是"DSH 用户被迫换界面范式"这个摩擦点。

商业模式

未披露。 MIT 开源，npm 免费安装，无定价、无托管、无赞助。

判断：纯流量打法。官方公众号收录带来的曝光是这个插件唯一的"商业模式"。它和 dsh-tianshu-tui 抢同一个 TUI 位置，但它的筹码是体验不是流程——体验类插件最容易被官方顺手内置，这是它最大的结构性风险。

四维评估

维度 结论
创始人-产品匹配度 作者自称极客、为 CLI 用户做，受众即自己
产品洞察力 把 Claude Code 的"终端体验"当产品来做而不是当 shell 皮肤，细节密度高（回滚、TPS、预警色）
技术实现质量 纯插件挂载、官方机制优先，工程干净；但 29 个 open issue 说明摊子大、修不完
市场时机 完美踩点官方无 TUI 的窗口；但官方移除过 TUI 又改走 Web UI，说明官方可能自认不需要终端界面，窗口可能被官方自己关上

判断

它卖的不是功能，是"不换习惯"——这是六件套里最懂用户心理的一个。

CLI 极客的迁移成本不在于"学不会新工具"，而在于"改变工作姿势"。dsh-TUI 的所有设计（像素鲸鱼、状态行、Esc 回滚、进度条）都在做同一件事：把 DSH 变成"我已经会用的那个工具"。双击 Esc 回滚尤其聪明——它没有发明新机制，只是把官方 fork 服务包装成了"撤销"这个人人都会的语义。

可迁移的规律：给"老用户习惯"做适配，比给"新用户功能"做加法更省力。 你的新产品如果底层更优但交互姿势和主流工具不同，最快的获客方式是做一个"姿势兼容层"——让老用户假装在用自己的旧工具，底层已经换了。

风险也很对称：体验层的护城河最浅。官方如果哪天把 TUI 加回来（它移走过一次，说明有这个能力），dsh-TUI 的像素鲸鱼救不了它。619 星是这个窗口期的红利，不是壁垒。

下一步看什么

① 官方是否重新内置 TUI——这是它最致命的单一变量 ② open issue 数量是否回落（现在 29 个）——修不完的插件会自己流失用户 ③ star/下载增长是否跟得上 DSH 本身增速——它是"补位"，DSH 涨它才涨

可借鉴的做法

产品逻辑：如果你的产品要抢"已有工具的替代品"这个位置，做一个"姿势兼容层"：把所有操作映射成用户已经在用的语义（撤销、回滚、命令菜单），而不是让他们学新概念。双击 Esc = 回滚这个包装，把"fork 会话"这种高级操作变成了零学习成本动作。

话术：可借鉴。它的 README 用"献给偏爱 cli 的各位极客"做受众声明，用"补位之作"做谦逊姿态——把"我抄了 Claude Code"翻译成"我给 DSH 补上了它缺的"，这个改写话术在中文开发者社区很有效。

定价结构：无。未披露。

结论

值得关注。 六件套里流量最高、心理洞察最准的插件，但护城河最浅。它验证了"姿势兼容层"这个获客机制的威力，也暴露了体验类插件在平台生态里的宿命——平台一动，皮肤全白。
