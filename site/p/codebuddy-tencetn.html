值得借鉴的一点

大厂在编程工具上砸资源，独立产品的空间正在被从下往上挤压

它替人省掉了哪一步

替代的是「在 IDE 里手动敲代码 + 在多个工具之间来回搬」的开发流程。 以前的流程是：需求文档一份、设计稿一份、代码环境一个、 部署平台又一个，中间靠人来翻译和搬运。CodeBuddy 的做法是 把「设计稿 → 代码 → 后端 → 部署」串成一条链， Figma 导入直接生成页面代码，PRD 自动生成，CloudBase 接后端， CloudStudio 出链接——中间的人工翻译环节被拿掉了。

可借鉴的做法

产品逻辑：做开发者工具时，「全形态覆盖」不是炫技而是覆盖不同人群—— 插件给日常补全（手动挡），IDE 给非技术用户（自动挡）， CLI 给专业开发者（赛道模式），底层模型和额度打通， 用户随场景切换不重复配置。如果你做工具，先想清楚三类用户 各自在哪个入口，而不是只做一个形态。

一句话定位

腾讯云的 AI 编程助手，插件、IDE、CLI 三种形态全都要—— 国内首家同时覆盖三种形态的编程工具厂商，从代码补全到 「对话即编程」到「终端里一句话驱动开发流程」全包。

做这个东西的人

腾讯云。这个 slug 的拼写有误（Tencetn 应为 Tencent），但产品本体明确。 CodeBuddy 是腾讯云官方产品，2024 年先以 IDE 插件形式上线（国内首个支持 MCP 协议的代码助手），2025 年 7 月 IDE 内测，2025 年 9 月发布 CLI 工具 CodeBuddy Code 并开放 IDE 国际版公测，成为国内首家同时支持 插件、IDE、CLI 三种形态的 AI 编程工具厂商。

判断：这是大厂「自家先用再对外」的典型产品。腾讯披露内部 90% 的工程师 在用 CodeBuddy，编码时间缩短 40%、AI 生成代码占比超 50%、 研发整体效率提升 16%——这些数字先说服自己，再对外卖。 大厂做编程工具的优势是资源无限、模型自研（混元）、云生态配套， 代价是它和独立产品的竞争从来不是同一场比赛。

它到底能做哪几件事

  • IDE 插件 → 日常编码补全、函数调用、业务逻辑与模板精准补全， 接入 IDE 工作流，国内版可调用 DeepSeek 等模型
  • CodeBuddy IDE → 独立 IDE，「对话即编程」：产品/设计师/初学者也能用 自然语言从构思到部署；支持 Figma 设计稿转页面代码、 智能文档生成（自动写 PRD）、CloudBase 后端接入、CloudStudio 一键部署
  • CodeBuddy Code（CLI） → npm 一键安装，在命令行用自然语言驱动 开发全流程：重构、修 bug、修 lint、解合并冲突、写发布说明， 可通过管道和 Git、npm 等工具链衔接
  • Plan 模式 → 对复杂需求做全流程拆解：需求分析、技术方案设计、 代码生成、验证测试自动化
  • 多模型架构 → 国内版用腾讯混元 + DeepSeek，国际版支持 GPT、Gemini 等， 三形态底层互通：模型互通、额度共享、体验一致

它明确不做：不做纯云 IDE 那种「必须迁移工作流」的产品—— CLI 形态专门强调「不改变开发者习惯」，接入现有工具链而不是要求换环境。

它在替代什么旧行为

替代的是「在 IDE 里手动敲代码 + 在多个工具之间来回搬」的开发流程。 以前的流程是：需求文档一份、设计稿一份、代码环境一个、 部署平台又一个，中间靠人来翻译和搬运。CodeBuddy 的做法是 把「设计稿 → 代码 → 后端 → 部署」串成一条链， Figma 导入直接生成页面代码，PRD 自动生成，CloudBase 接后端， CloudStudio 出链接——中间的人工翻译环节被拿掉了。

CLI 形态替代的是「人守在终端前逐条敲命令」。 以前让电脑干活要么写脚本要么手动执行；CodeBuddy Code 支持 「生成测试代码 → 直接执行测试」的连续动作，描述一遍需求 （甚至截图 + 自然语言），它就建分支、写代码、提 MR。

在国内团队场景，它还替代了「用海外工具时的数据出境顾虑」： 国内版 100% 国内模型、等保三级，金融/政务场景不能把代码 发给 GitHub Copilot 这类国际产品，CodeBuddy 吃的是这个合规位。

商业模式

  • 个人/国内版：免费使用，可调用 DeepSeek 等模型
  • 国际版：IDE 与 CLI 共用额度，测试期间赠送部分体验额度，后续按订阅收费
  • 企业：按需付费

判断：免费策略和大厂一贯做法一致——编程工具是入口，后端云服务 （CloudBase、CloudStudio、腾讯云）才是要变现的地方。 它跟 Cursor 拼的不是价格，是「在腾讯云生态里从代码到上线一条龙」。 这个绑定越深，独立开发者越难复制。

硬数字

  • 流量榜：月访问 749 万，环比 +30%（2026-08），进代码辅助榜
  • 腾讯内部：90% 工程师使用，编码时间缩短 40%+，AI 生成代码占比超 50%， 研发整体效率提升 16%+（腾讯云官方披露，2025-09）
  • 国际版评测口径（IDC/厂商引用）：复杂工程任务完成率 92%、 国内平均响应延迟 120ms（对比 Cursor 等 300-380ms）
  • 2025 年 9 月 CodeBuddy Code 发布，CodeBuddy IDE 国际版同步公测

判断

值得关注——它是大厂编程工具的正面样本，数字是真的。

749 万月访问、环比 +30%，在国产编程助手赛道是第一梯队。 腾讯内部 90% 工程师使用、提效 16% 是产品团队自己 dogfooding 出来的数据， 比外部评测更可信——一个工具敢说「自家 90% 的人在用」， 说明至少内部是真的好用。这个「先让自家用」的做法，是独立产品 很难复制的冷启动方式。

它真正的优势是「从代码到上线」的闭环，不是代码补全本身。 Cursor 强在单机编辑体验，CodeBuddy 强在设计稿、代码、后端、部署 全在腾讯生态里。对一个用腾讯云的中小团队，这个闭环的摩擦 远小于「Cursor + 自建后端 + 自选部署」的拼装方案。

要打的问号：国际版是它证明自己的战场。国内免费 + 合规 是防守逻辑，国际版要和 Cursor、Copilot 拼模型和体验， 目前只有「测试期间赠送额度」，没有公布付费转化数据。 另外 30% 的 mom 增速与竞品（豆包 MarsCode、通义灵码）一起 都在增长，这个市场是红海，不是增量。

下一步看什么

① 国际版付费上线后的订阅用户数——免费赠送转付费的转化率是硬指标 ② 月访问能否站稳千万级并持续正增长——当前 749 万仍在爬坡期 ③ 有没有公开的中大型企业（非腾讯系）case study——「自家用」之外 有没有外部客户买单

可借鉴的做法

产品逻辑：做开发者工具时，「全形态覆盖」不是炫技而是覆盖不同人群—— 插件给日常补全（手动挡），IDE 给非技术用户（自动挡）， CLI 给专业开发者（赛道模式），底层模型和额度打通， 用户随场景切换不重复配置。如果你做工具，先想清楚三类用户 各自在哪个入口，而不是只做一个形态。

产品逻辑（先自用）：内部 dogfooding 是最好的冷启动。 「90% 内部工程师在用」这个数字本身就是销售素材—— 工具敢把自家研发效率数据拿出来，比任何 benchmark 都有说服力。 独立产品可以先在团队内部跑出可公开的效率数字，再对外。

话术：无。产品页是厂商话术，没有可偷的句式。

结论

值得关注。 大厂编程工具里最值得盯的样本之一：内部数据真实、 全形态覆盖完整、腾讯云闭环是差异化。风险在红海竞争和 国际版付费验证未完成。它是「大厂做开发者工具」这条路线的 正面和反面教材都齐了的产品。
