使用场景

AI 应用后端工程师在让 Agent 自动生成并运行代码时，需要把这段不可信代码放进隔离环境执行，再把运行结果交回主流程，避免影响生产系统。

常见做法是用容器、微虚拟机或现成沙箱服务自行拼装执行环境，或干脆限制 Agent 只能调用白名单工具、不执行任意代码。

模型生成的代码不可信，直接在本机或生产容器里跑有安全和资源风险；自建隔离环境要处理启动速度、内存开销和逃逸防护，是重复且容易做错的一步。

xOcto 的判断

问题已识别，需求强度未明

趋势是 Agent 执行代码的隔离层正在被大厂开源，沙箱本身会快速变成免费零件。切入不在重做一个更快的沙箱，而在它上面那层没人愿意自己搭的东西：谁负责给企业内 Agent 的执行结果做审计留痕、配额与合规边界，按执行次数或合规报告收费，而不是按席位卖工具。
