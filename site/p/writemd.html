03

60 秒生意判断

先给出判断与下一步，再保留完整证据和反例。

一句话定位

一个免费、开源（Apache-2.0）、可以完全换肤的 macOS Markdown 编辑器： 它不预置主题，而是给你一套外观控制（字体、字号、行高、配色、透明度、玻璃质感、 图片/视频背景），让你把编辑器的"房间"改造成自己的样子，存成配置随时切换； 文档永远是普通的本地 md 文件。

做这个东西的人

Daniel Bilek 单人开发、单人维护（GitHub: danielbilek/writemd），2026-07-04 建仓库， 2026-08-11 以 Show HN 发布，已迭代到 v1.0.1。仓库 README 注明 "Built by Daniel Bilek with Jean2"——Jean2（jean2.ai）应该是一个 AI 编程工具， 即这个编辑器本身是 AI 辅助开发的产物（不确定其具体形态，未进一步核实）。

注意区分：Mac App Store 上另有一个叫 "write.md" 的应用（Gotaru 公司出品， 富文本编辑存成 Markdown），和这个开源项目是两个完全不同的产品。

判断：这是"AI 时代个人开发者也能做出成品级 macOS 应用"的又一例证—— 单人、两个月、v1.0.1，质量能上 HN 前几页。作者在 HN 上直接回应 "为什么不叫原生应用"的质疑（老实承认是 Electron），姿态很路人缘。

它到底能做哪几件事

  • 外观配置文件 → 字体/字号/行高/页面宽度、文字/背景/强调色/边框色、 窗口透明度/玻璃效果/边框、单区或分栏、图片/视频背景，全部可调并存成 可命名、可切换的 profile
  • 不预置主题 → 官网明说"不卖主题包"，示例全是用自身控件调出来的—— 把"换肤"做成了用户自己动手的能力而不是商店里的商品
  • 可选的小工具 → Vim 模式（不用开 IDE 就能模态编辑）、本地美式英语拼写 与基础风格建议（无 AI 服务、无账号）
  • 三种视图 → 统一编辑器 / 渲染预览 / 分屏
  • 状态栏信息 → 文件名、字数、阅读时长、纠错数、Vim 状态
  • 纯本地文件 → 打开保存 .md/.markdown/.txt，无遥测、无分析、无登录

它明确不做：不绑定云、不设账号、不做 AI 写作服务、不上传任何文档内容 （只有检查更新时向 GitHub Releases 发一个不含文档内容的请求）。

它在替代什么旧行为

以前用 Markdown 写东西的桌面编辑器，主流是 Typora（付费、所见即所得）、 Obsidian（免费、以笔记库/双链为核心）、MacDown（老牌免费但已多年未维护， HN 上有用户说它快在 Rosetta 下跑不动了）。这三者的共同模式是： 编辑器给你一套固定外观，你适应它。

Write.md 把这个关系倒了过来——编辑器适应你：调整的不是语法高亮配色这种 表面层，而是整个写作表面的材质（字体、透明度、背景）。它替代的是 "为了想要一个深夜写作环境，得在无数设置里妥协"的旧体验。 它不追求功能最多，追求"写作的场地感"这件事做到位。

商业模式

没有。 免费、开源、无内购、无云服务、无付费计划。

判断：这是典型的"认真做、免费放"的个人项目。它的商业价值不在收入， 而在三点：作者的作品集证明（v1.0.1 的质量本身就是简历）、 HN 曝光带来的个人品牌、以及"免费"作为对 Typora 付费/Obsidian 复杂化的 一种态度表达。对读者来说，值得抄的不是它的商业模式（没有）， 而是它怎么用"外观配置"这个别人看不上的功能做出差异化。

硬数字

  • HN Show HN：86 分、68 条评论，讨论质量高（Typora/Obsidian 对比、Electron 争论）
  • GitHub：12 次提交（单人）、v1.0.1（2026-08-12）、Apache-2.0
  • 当前仅支持 Apple silicon Mac，签名并公证的 DMG 发布在 GitHub Releases
  • 技术栈：Electron + TypeScript + React + CodeMirror 6 + Bun

四维评估

维度 结论
创始人-产品匹配度 作者为写博客造了个趁手的编辑器，自己就是第一用户，动机真实
产品洞察力 把"外观可配置"从边缘功能提升为产品主题——大多数人只做语法高亮，它做整个房间
技术实现质量 Electron 单文件包 + 签名公证 + 自动更新 + 12 提交就到 1.0.1，工程流程完整
市场时机 编辑器红海，但"场地感/氛围"这个角度没人占住；时点上无优势也无劣势

判断

这是一个"功能红海里做体验细分"的案例，值得抄的是它的取舍逻辑。

Markdown 编辑器功能已经卷到天花板：双链、插件系统、AI 续写、同步……谁都能列。 Write.md 一个都没做，只押一个别人不押的点——写作空间的材质感。 它把这个点做成了一等公民：预置主题不卖、用户自己调、调完存 profile。 这个取舍让它在一堆"功能更多"的编辑器里有了一个清晰的身份： 不是另一个 Typora，是"能把编辑器改成深夜书房"的那个。

代价也清楚：这个差异化的买单人群有限。氛围党是真实存在但小众的群体， 而且 Electron 的体积/性能在原生党那里是扣分项（HN 上有用户直言 "Made for Apple silicon 却是个 Electron 应用"会劝退人）。 它大概率会停在"小而美的免费工具"，不会变成一门生意。

可迁移的规律：当品类功能已经卷无可卷时，找一个"体验向"的切口单点打透—— 功能红海里，情感价值（写字的氛围感）反而没有竞争者。 但要注意：体验向差异化通常意味着小市场，适合个人项目立身， 不适合指望它成为大生意。

下一步看什么

① GitHub star 三个月后是否破千——免费开源编辑器的主要扩散指标 ② 是否出现社区贡献的主题配置分享——"用户自建皮肤"若形成分享社区，就是差异化成立 ③ 作者是否把它推上 App Store 或转为付费——判断作者是把这当作品集还是当产品

可借鉴的做法

产品逻辑：把用户能自己改的东西做成"能力"而不是"商品"。Write.md 不卖主题， 给你调主题的控件——这让每个用户调出来的东西都独一无二，产品因此天然 产生"我的专属版本"的拥有感。做个性化产品，给控件比给模板更能留住人。

定价结构：无。但"免费 + 无遥测 + 无账号"作为个人项目的默认姿态值得 参考——小工具没有商业压力时，把隐私做干净本身就是差异化。

结论

值得关注。 功能上没有新东西，但"写作空间的材质感"这个体验切口在 编辑器红海里确实没有对手，工程完成度也配得上 HN 的关注。 它大概率成不了生意，但作为"红海品类里做体验细分"的样本，可借鉴性高。 三个月后看它有没有形成用户自建皮肤的小社区。
