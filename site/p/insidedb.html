一句话定位

一个把数据库内部原理做成可交互动画的网页——插入一个键，看 B 树怎么分裂；拔掉电源，看 WAL 怎么把数据救回来。用"玩"替代"读"，讲清楚 B 树、查询计划、预写日志和 MVCC 四个主题。

做这个东西的人

作者 GitHub 账号 david-g-3654（David G.），个人项目，托管在 GitHub Pages 上，仓库创建于 2026-08-11，与 HN 发帖同日。团队背景、动机未披露。

判断：这是典型的"讲不清不如做出来"型作品。作者大概率是被"怎么跟人解释数据库"逼出来的——因为静态图解释不清，才做了动画。

它到底能做哪几件事

  • B 树 → 插入键时实时看节点分裂、中间键上移，能看到树高与"找到任意键的读取次数"
  • 查询计划器 → 同一个 WHERE 跑两种计划（全表扫描 vs 走索引），直观对比 cost 估算怎么选
  • 预写日志 → 一步步把写入、提交、拔电、恢复的时序演给你看
  • MVCC → 读与写互不阻塞的版本化机制

每个主题都是一段可操作的动画，不是静态图解。

它在替代什么旧行为

以前学数据库内部原理，靠三样东西：教科书（静态图）、博客长文（ASCII 图和文字描述）、以及别人录的教学视频（只能看不能动）。

这个页面把"读图+脑补"换成"亲手操作"：你自己插入键、自己拔电源、自己换查询计划。对"搞懂"这件事，可交互解释器比文字快得多——但它只覆盖了四个主题，没有系统性课程结构，替代的是"查一个知识点"的动作，不是"学一门课"。

商业模式

无。纯免费教育页面，无广告、无付费、无课程衍生。

判断：这类单页解释器通常是为了名气或求职作品集，而不是生意。它的商业价值在于证明作者能把复杂系统讲明白——这是能被招聘市场定价的能力。
