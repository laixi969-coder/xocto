stoaexchange

重点研究 基础层
它替人省掉了哪一步

买 GPU 现在的实际流程是：挨个问 OEM 的销售拿配额报价、问云厂商有没有余量、 托朋友找经纪商、在二手渠道碰运气。每一路的报价口径都不一样， 你没法知道自己拿到的价格是好是坏。

可借鉴的做法

产品逻辑：不做撮合，先做基准。 先让所有人都来看你的价格，来的人多了，交易自然发生在你这里。 这条对任何「信息不对称严重、单笔金额大」的行业都成立 —— 地产、二手设备、大宗商品，结构和 GPU 是同一个。

可借鉴的做法

产品逻辑：多 Agent 工作流要从「一个人用」变成「团队用」， qm 的分域结构值得参考 —— 每人一个隔离工作区 + 一个共享技能库 + 管理员定可用模型。 这三件事的组合，比做一套权限系统简单得多，效果一样。

shuohao-skills

重点研究 AI + 创作
它替人省掉了哪一步

短剧改编的前期工作。以前这一段是：编剧读完小说 → 手写人物小传 → 美术出设定图 → 导演排分集大纲 → 制片列资产清单。一个团队三到五人，一部剧的前期做一到两周。

可借鉴的做法

产品逻辑：它把「从小说到可开拍素材」这一段做成了标准件， 补的正是所有「从灵感到成片」类工作流都缺的上游环节。 它的 13 道质量门尤其值得看 —— 把创作质量变成脚本能检查的硬约束， 这个思路可以搬到内容流水线的每一个环节上。

值得留意

已经看清它解决的问题，仍在等待更多证据
  • human-review 像批注 Google 文档一样给 AI 的产出留意见 AI + 开发开源关注 932

    反馈的形态决定采纳率，让人用熟悉的批注方式说话，比教他写 prompt 快
  • LongHorizon-Harness 让 agent 连续操作电脑几小时而不丢任务状态 基础层开源关注 675

    agent 的价值分水岭是能连续干多久，不是单步准不准
  • mcp-server 给 agent 开电话号码，两百多个国家，验证码自动读回来 基础层开源关注 612

    agent 要办事就得有身份，而身份的最小单位是手机号——这是条被忽略的生意
  • DeterminFlow 面向生产的 AI 工作流运行时，能校验也能恢复 基础层开源关注 373

    把「可恢复」做成卖点，说明 AI 工作流已经进了不能丢单的场景
  • discoveredmaterials 用 AI agent 找新材料的实验室 AI + 商业社区热度 143

    agent 进实验室这类活，壁垒在实验数据和设备，不在提示词
  • ShenNongMi 中医知识图谱问答，靠两万个节点撑住会自我纠错的查询 AI + 生活开源关注 103

    垂直知识图谱是模型抹平不掉的壁垒，谁手上有结构化的行业知识谁就有护城河
  • approving 把 coding agent 的活变成可审批、可回滚的交付流程 AI + 开发开源关注 77

    agent 越自动，人越需要一个卡点，审批这一环本身就能做成产品
  • ai-short-drama AI 短剧的故事骨架、剧集连续性和可续跑的成片流程 AI + 创作开源关注 47

    连续性才是短剧工业化的卡点，单集好拍，十集不崩才值钱
